## 方法一：先确定比例，再验证整条裁切路径

### 公开依据

FFmpeg 官方文档说明 crop 的 x/y 按帧求值，不合法坐标会近似到合法值；scale 可保持原比例，并区分像素比例 SAR 与显示比例 DAR。zoompan 分别设置输出尺寸、帧率和持续帧数。[官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)

本轮 HTML 正文读取超时，实际核读的是[FFmpeg 官方仓库文档源码](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/doc/filters.texi)的 crop、scale、zoompan 章节。master 是可变文档，不代表本机安装版本；实际操作前应核对已安装版本的帮助。本文未运行 FFmpeg，也不将以下数学检查冒充其滤镜实测。

### 制作建议

1. 先写清源画布、输出画布和裁切窗。方形像素的 9:16 输出，裁切窗也采用 9:16，再等比例缩放；不要将整个横图直接非等比拉成竖图。源 SAR 不为 1 时先核显示比例，不仅比较宽高整数。
2. 若竖裁损害人物关系、实验装置或必要标识，保留横幅嵌入，不强行铺满。静态资料的平移缩放仍是静态资料，不当作真实动态记录；需要真实动作证据时另选有权使用的动态素材。
3. 对每一输出帧记录实际裁切框 x、y、cw、ch，检查 0≤x≤W−cw、0≤y≤H−ch，且 0<cw≤W、0<ch≤H。变焦时宽高也随帧更新，旋转等额外变换需另算变换后的边界。
4. 区分“设计坐标越界”和“输出有黑边”。软件可能自动钳制坐标，使越界表现为突然停顿而非黑边；不能从无黑边反推路径正确。也不能把钳制后不越界当成运动自然。
5. 对编码后的真实像素再检查人物、圆形参照物、文字、边缘与运动连续性。数学通过只覆盖已建模的几何约束，不能证明对象未被裁掉、字幕可读或画质合格。

### 实验 A：三帧抽查能否漏掉中途越界

合成输入，无影像文件：源画布 W=1600、H=900，裁切窗 cw=450、ch=800，y=50，输出目标 360×640。共 121 个检查点，索引 n=0…120，u=n/120。

故障路径为 x=575+600×sin²(2πu)。这是专门构造的故障注入，不是推荐镜头运动。检查首、中、末 n=0、60、120，再检查全部索引；候选修正只将 x 限制在 [0,1150]，其余不变。

可复现 JavaScript，无依赖，运行在普通 JavaScript 环境：

```js
const W = 1600, H = 900, cw = 450, ch = 800, y = 50, N = 121;
const xAt = n => 575 + 600 * Math.sin(2 * Math.PI * n / (N - 1)) ** 2;
const invalid = x => x < 0 || x + cw > W || y < 0 || y + ch > H;
const bad = [];
let after = 0;
for (let n = 0; n < N; n++) {
  const x = xAt(n);
  if (invalid(x)) bad.push(n);
  if (invalid(Math.min(W - cw, Math.max(0, x)))) after++;
}
console.log({
  threeFramePass: [0, 60, 120].every(n => !invalid(xAt(n))),
  badFrames: bad,
  badCount: bad.length,
  after
});
```

本轮实际数值结果：
- 三点检查全部通过。
- 全索引检查发现 14/121 个点越界：27–33、87–93；最大越出右边界 25 个源像素。
- 钳制后数值越界为 0/121；没有据此宣布视觉修复成功。
- 若直接把 1600×900 非等比映射到 360×640，横纵缩放分别为 0.225 与约 0.7111；几何比例会变形。450×800 裁切窗映射到 360×640 则两轴均为 0.8。这是算术推导，不是渲染测量。

结论仅为：这个已知合成用例能被全序列检查发现，而首中末抽查漏检。121 是测试集大小，不是实际视频的默认采样量；实片应覆盖实际输出全部帧，变帧率时按实际时间戳计算。不能推广成任意路径、任意渲染器的检出率。

下一步拟执行：用自制圆形、方格与边缘标记测试图渲染两版，检查全输出帧以及正常速度回放。特别观察钳制区间是否产生停顿；若有，调整合法路径而非直接放行。达到完整帧记录与审看记录后停止；缺渲染环境或实际审看就保留未检查，不补写通过。

## 方法二：旁白连续，资料画面的切入点单独验证

### 公开依据与适用范围

Adobe 定义 J cut 为下一场景声音先于画面出现，L cut 为前一场景声音延续到下一画面；两者属于声画切点不同时发生的 split edit。[Adobe 官方说明](https://helpx.adobe.com/premiere/desktop/edit-projects/trim-clips/perform-j-cuts-and-l-cuts.html)（页面更新 2025-08-22）。

Television Academy 对 Ken Burns 的报道描述其组合照片、音乐和旁白的历史叙事方式。[公开报道](https://www.televisionacademy.com/features/news/features/ken-burns-effect)（2015-06-22）。本轮只读报道，没有完整观看影片；该历史例子不证明短视频留存，也不提供照片复用授权。

由此提出编辑实验：先固定正常语速的完整旁白，仅调整资料画面何时进入。贯穿全段的同一旁白加画面切换，不自动构成严格意义的 J/L cut；这里只借鉴声画节奏可分开安排的思路。

### 实验 B：只改变一个资料画面的进入时刻

状态：尚未执行。使用自有或权利明确的 20–30 秒测试段，长度仅为操作示例，不是平台阈值。

- 选择一个已核事实的解释段，包含“提出对象→解释作用→说明限制”。固定脚本、完整音轨、语速、字幕、素材、总时长和其他切点。
- A 版：目标资料画面在对象被说出时进入。
- B 版：同一画面提前约 0.4 秒进入，其退出时刻不变。0.4 秒是预设测试值，不是最佳值；提前显示会同时改变前后镜头的占屏时长，应完整记录这个切点改动，不能声称仅改变注意力。
- 保持口播不截字、不补空白、不循环。若资料带同期原声，应明确是否使用，不能让新增旁白像当事人发言，也不能凭音桥暗示不成立的事件连续关系。
- 在既定出镜布局内测试背景资料切点。若项目要求主持常驻，保持不变；“无出镜、连续旁白”的独立样式可另行提案，但不能借本实验擅改现有制作规范。
- 预先写出两道理解题：这件东西做什么？该段说明了什么限制？请同意参与的少量测试者随机只看一版，记录实际人数、正确复述人数和误解内容，不收集姓名或账号。人数由可行条件预先确定，不将探索样本当统计证明。
- 两位审核者另行正常速度带声审看，分别记录提前画面是否泄露不相关信息、是否造成错指，以及切点是否自然。无人实际参与时不虚构偏好或理解率。

护栏：任一版本出现事实误导、缺句、必要标识不可读或明显接缝问题，先退回修复，不把故障版作为运营对照。停止条件为预定样本完成，或 7 天观察窗结束；未凑齐填样本不足。七天是实验管理约定，不是流量周期。
