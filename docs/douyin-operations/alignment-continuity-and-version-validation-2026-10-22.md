# 口播对齐：独立锚点、连续动作与版本差异实验

核验日期：2026-10-22（北京时间；UTC 2026-10-21）。
性质：公开技术依据、制作建议与尚未执行的离线实验，不是抖音或小红书新增规则，也没有播放、完播或转化效果结论。

本文补充[制作复盘手册](video-production-operations-review-public.md)的视听验收要求。增量重点是：避免词码重复加权、避免把播放掉帧当剪辑缺陷、分清文件变化与独立主题。不同平台发布仍须分别核查权利、AI声明、实际排期与时区；学习实验不自动授权发布。

## 一、保留完整词和数字，先排除诊断误报

### 官方依据及边界

PyTorch 的强制对齐教程处理语音与转录文本，返回 token 的对齐及评分；它没有检查人物嘴部画面。当前页面说明相关接口在 TorchAudio 2.8 弃用、2.9 移除。因此仅引用方法，不建议照旧教程安装最新版并调用已移除接口。[官方教程](https://docs.pytorch.org/audio/stable/tutorials/ctc_forced_alignment_api_tutorial.html)

以下是由该边界推导的制作建议，不是官方指定算法：

- 保存原始词、原时间区间、置信度、规范化后的文本，以及两者的对应关系。规范化不能不可逆地丢掉小数点、百分号、负号、单位或否定词。
- 把整词拆成多个字符时，若它们共享同一个词级时间区间，不能当作多个独立时间锚点重复加权。
- 数字串须整体匹配。例如虚构测试文本“比例为12.5%”不能只匹配最后一个数字就宣称完整数值已对齐。
- 低置信度、异常长词跨度、缺失词或少数锚点应标记待核。语音识别漏出一个词，不等于原声真的漏读。
- 只报告对应音频之间的时间线差异。中点误差下降，不等于视觉口型改善；不得直接触发变速或放行。

### 实验 A：诊断逻辑故障注入

使用自有或有许可的测试句，不使用真实账号数据。预先固定普通句、含数字与单位句、否定句、低置信度句四组。

1. 对同一份词码制作两个离线解析版本：逐字中点基线，以及保留词/数字跨度并去除重复权重的候选。
2. 注入共享词时间戳、数字标点丢失、异常长词区间三种输入问题，保留未破坏的对照。
3. 记录独立锚点数、未匹配文本、误差分布和被标记的范围，不能仅记录全局平均数。
4. 通过可靠的正常速度视听复核建立参考判断后，才统计误报和漏报。参考判断未完成时，只交诊断差异，不计算“准确率”。
5. 停止条件：预先固定的测试集跑完，或缺少原始词码/可靠参考判断。后者记证据不足，不反复改规则直到结果变好。

结果模板：测试组、输入故障、独立锚点数、规范化损失、标记区间、参考判断是否存在、误报/漏报、未确定项。

## 二、先排除播放问题，再判断剪点是否自然

Adobe 的 Morph Cut 说明建议选择自然停顿、相近头位，并渲染预览后判断。适用条件偏向单人、固定机位、静态背景；大量动作不保证能自然平滑。[Adobe 官方说明](https://helpx.adobe.com/premiere/desktop/add-video-effects/apply-video-transitions/morph-cut-overview.html)

这不是要求使用 Morph Cut，也不是用生成中间帧掩盖口型错误。软件预览卡顿与导出文件本身的跳变，应分开排查。

### 实验 B：连续窗口对照

- 从有许可的连续口播中选一个剪点，保留前后完整短语和上下文。原片与候选都包含相同语音内容。
- 先导出短窗口，再正常速度带声音播放；确认播放器不存在明显掉帧。若播放条件不可靠，记录“暂不能判断”，不宣布剪辑合格或错误。
- 原剪点与候选采用匿名代号并交换播放顺序。分别记录头部方向、眼神/眨眼、嘴部、照明、语音完整性，以及自然度理由和时间码。
- 逐帧只帮助定位问题。不得为了闭口接点删掉首尾字，也不得为了指标好看强行加速、拉慢、冻结说话帧。
- 结束条件：完成约定的两份独立审看记录，或无法保证播放质量。两份记录是实验设计，不是平台审核人数要求。
- 无法形成一致结论就保留原素材与候选，并标记未验收；局部实验通过后仍检查最终全片。

本实验不比较缩窗运动曲线或封面字号，避免与已有相应实验重复。

## 三、把文件差异定位与主题去重分开

FFmpeg 的 framehash 可输出逐音视频包哈希，包含流编号、DTS、PTS、持续时间、大小等信息，默认哈希算法为 SHA-256。输入通常经转换后计算，比较时必须记录并统一解码/输出参数。[FFmpeg 官方文档](https://ffmpeg.org/ffmpeg-formats.html#framehash)

### 实验 C：四类版本的预期结果

使用同一许可素材，保留源文件并另存测试副本：

| 副本 | 应检查的变化 | 不应自动推导的结论 |
|---|---|---|
| 仅重封装 | 文件字节及容器变化；统一条件下解码内容和时间戳 | 新主题 |
| 仅改发布封面文件 | 封面资产变化；视频可保持不变 | 新长片库存 |
| 有损重新编码 | 文件/解码帧哈希可能改变，核对参数 | 内容独立或质量更好 |
| 替换音轨 | 音频与时间线差异，画面可能不变 | 口型自动同步 |

- 文件层保留原文件 SHA-256，必要时增加逐包哈希与时间戳证据。仅哈希值相同但时间戳不同，也不能忽略播放时序差异。
- 内容层保留主题ID、脚本版本、音轨版本、剪辑版本、验收状态与发布记录。同主题多平台导出或派生预览归到同一主题，不重复计数。
- 固定工具版本和比较参数后，检验四类副本是否按预期被归类；不声称有损重编码后哈希应相同。
- 停止条件：四类副本均完成记录，或比较参数无法统一。后者记不可比，不自动判重复或独立。
- 静止帧重复不自动等于凑时长；不同哈希也不自动等于原创。内容深度、使用权与完整视听验收另行判断。
