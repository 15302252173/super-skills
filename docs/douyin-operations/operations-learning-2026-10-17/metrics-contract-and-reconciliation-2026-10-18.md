# 真实指标复盘补充：口径字典、快照修订与汇总验收

资料核验：2026-10-18（UTC）。适用：科技人物视频的抖音、小红书运营复盘。

配合[执行手册](README.md)和[既有数据口径说明](../video-production-operations-review-public.md)使用。本文不重复单日与累计、发布龄、缺失值和制作双审核要求，新增三件事：为每个数据产品锁定指标定义；保留同一统计窗口的修订记录；检验汇总方法是否改变结论。

本文是方法建议，不是已执行的数据实验，也没有账号表现结论。公开仓库仅保存方法、空模板及明确标注的合成算例；真实后台记录放在受控位置。

## 一、同个平台也不能共用一套指标定义

本轮官方资料提供了三个有边界的例子：

1. 抖音开放平台“获取视频基础数据”说明：首次授权后的完整数据存在等待时间，之后有次日刷新安排，并限制可返回数据的视频创建范围。这是该接口的条件，不是创作者后台全部字段的实时性保证。[官方接口说明](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/video-data/get-basic-data/)

2. 抖音“小程序挂载短视频分析”说明了前一日数据的更新安排；部分人数指标按单日去重、选定周期累加。因此，跨日相加不等于整个周期的独立人数。该页面只适用于其标明的小程序挂载场景。[官方数据分析说明](https://partner.open-douyin.com/docs/resource/zh-CN/mini-app/operation/data/data-center/video)

3. 小红书蒲公英帮助内容区分了蒲公英离线更新和聚光实时数据，并说明不同模块的互动构成存在差异；互动数据也不一定能按流量渠道拆开。这些条件不能直接套用普通创作者后台。[蒲公英官方帮助](https://pgy.xiaohongshu.com/help/detail?id=97e5a307cc23aeefc7295c76926088c6&userType=4)

上述依据支持的结论是：先确认正在读哪个产品、模块、字段和窗口，再讨论增长。不能因为同属抖音或小红书，就拼接它们的分子和分母。

### 最小指标字典

每个实际使用的字段建一行：

| 字段 | 填写要求 |
| --- | --- |
| metric_key | 内部唯一代号，不能只写“播放”或“互动” |
| platform / product / module | 平台、具体产品、页面或报表模块 |
| raw_label / definition | 平台字段原名、定义原文所在位置 |
| unit / grain | 次、人数、秒或比例；单作品、单日、账号等粒度 |
| window / timezone | 累计、自然日或自定义窗口；时区依据 |
| numerator / denominator | 比例实际使用的分子与分母；不可见则留缺失 |
| traffic_scope | 自然、推广、混合或未知 |
| dedup_scope | 去重对象及周期；未说明则写未知 |
| refresh_rule | 官方说明或界面提示；记录适用产品 |
| verified_at / evidence | 核验日期和可复核依据 |
| definition_version | 本轮采用的定义版本 |

只有“名称相似”不能判定为同一指标。未经确认，不把播放次数、观看人数、阅读和曝光统一改名为 views。

定义发生变化时新建版本，保留旧版。无法证明新旧口径一致，就在趋势图中标断点，不强行拼成连续增长曲线。

## 二、采集快照和统计窗口分开存

沿用既有实际公开时间与采样时间，再增加：

- requested_window：本次想观察的窗口，例如发布后24小时。
- reported_window：平台实际给出的统计窗口。
- data_through：平台明确说明的数据截止；未说明则为 unknown。
- collected_at：实际读取时刻。
- snapshot_id：这次读取的唯一记录。
- revision_of：若再次读取同一统计窗口，指向旧快照。
- availability：available、pending_refresh、not_provided、read_error、scope_unknown。
- analysis_status：可比较、暂存观察、不可比较。

### 三条处理规则

1. 到了发布后24小时，但页面只覆盖到昨日，不把这次数据标成完整24小时表现。保存真实窗口；待数据条件满足后再形成对应分析记录。
2. 同一固定窗口再次读取出现变化，保留两次快照和差值，标“窗口数据修订”；不要覆盖旧值，也不要将修订差值叫作新一天增长。
3. 累计值下降不自动判错，也不自动归因于异常流量清理。先核账号、作品、过滤条件、窗口、定义版本和页面提示；没有原因证据就保持待核。

数据更新时间、采集时间和统计截止不是同一件事。连续两次读数相同也不能证明平台已经完成结算。

缺字段、权限不足或取数失败时，不为补表开通新权限、生成凭证、切换未经授权的数据来源或购买工具。

## 三、汇总前先决定自己想回答什么

### 1. 比例不能只求平均

以下是合成算例，不是账号成绩：

- 作品A：1次目标行为 / 10次合格分母，比例10%。
- 作品B：9次目标行为 / 1000次合格分母，比例0.9%。
- 两条比例的简单平均：5.45%。
- 合并事件比例：10 / 1010，约0.99%。

两者回答不同问题。前者给每条作品相同权重，后者给每次合格分母事件相同权重。报告必须明确选哪一种，并保留单条分子、分母；不能根据哪一个更好看来更换算法。

只有单位、窗口、定义、流量范围一致且可相加时，才合并分子与分母。涉及人数时还要核去重规则，不能把同一观众在不同作品或不同日的重复出现算作全周期唯一观众。

### 2. 平均观看时长也有权重条件

跨作品汇总时，优先使用平台提供的总观看时长及其对应计数口径。缺少相容分母时，只展示逐条平均观看时长或明确标注的作品层面汇总，不根据其他播放字段猜出“总体平均观看时长”。

### 3. 总体变化先检查来源构成

推荐、搜索、主页等来源的比例变化，可能改变总体表现，即使每个来源内部没有改善。

实际后台提供可比的分来源分子和分母时，先分层比较，再看总体。只给来源占比、未给对应行为数时，不能推算各来源转化率；不能拆自然与付费时，维持混合口径。

这一步用于排除可能的其他解释，不能单独证明封面、人物缩窗或剪辑造成了增长。

## 四、一次可验证的数据验收实验

状态：尚未执行。目标是验证记录流程能否阻止错误结论，不测试推荐算法。

### A. 无账号合成测试

将以下三个案例交给台账或分析流程，检查输出：

| 输入案例 | 必须得到的结果 |
| --- | --- |
| 上述两作品比例数据 | 同时识别5.45%的作品等权均值与约0.99%的合并事件比例，名称不混用 |
| 同一固定窗口两次读取数值不同 | 生成修订关系，旧记录仍在；不生成“当天新增”结论 |
| 仅有按日去重人数，两天存在重复观看可能 | 不输出两天整体独立观众总数 |

这些测试通过只代表流程处理符合预期，不代表真实后台指标已验证。

### B. 获准后台的只读对账

下一次已有授权的数据复盘中，选择一条已公开作品：

1. 记录所用产品、模块、字段、筛选条件和定义版本。
2. 在既定采样时点保存一次快照，区分目标窗口与实际窗口。
3. 若有明确刷新说明，在其对应刷新条件满足后回读同一固定窗口；没有说明就记录未知，不自行承诺刷新时间。
4. 如页面与已有导出都可读取，核对两者的作品范围、窗口、单位和过滤条件；不能对齐时登记差异，不强制“对平”。
5. 输出一页结论：哪些字段可比较、哪些仍缺证、是否发生修订、哪些增长判断因此不能成立。

停止条件：所选窗口的字段完成映射并能复现，或因定义、权限、窗口不可得而明确标为不可比较。不要为了获得漂亮结论继续增加数据源、投放或重复发布作品。

## 五、给下一轮内容实验的使用门槛

封面和自然动作接续实验仍按原手册逐项开展；本补充只决定哪些数据有资格进入结论：

- 指标定义与产品范围相容；
- 实际统计窗口可比；
- 快照及修订可以追溯；
- 分子、分母与汇总方法明确；
- 缺失值、混合流量及来源变化已经披露。

不满足时，保留制作判断和人工理解测试结果，增长结论写“证据不足”。不要由数据未刷新推断内容失败，也不要由不同模块数据不一致推断平台限流。

## 来源核验边界

本轮资料查阅日期为2026-10-18（UTC），不是页面发布日期或新规生效日。

- 抖音小程序挂载分析页直接打开并取得正文。
- 抖音视频基础数据接口说明与小红书蒲公英帮助页：取得官方域名搜索索引正文；直接打开超时。本文仅采用检索正文明确出现的内容，不宣称全文或当前账号界面已经核验。
- 未将第三方转载、普通用户视频或名称类似官方的站点作为平台规则依据。
- 上述接口与商业产品帮助只用于说明具体的数据条件，不构成接入建议，也不授权调用接口、开通产品、投放或公开账号数据。
