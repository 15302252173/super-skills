# 视频生产与发布质量检查补充

更新／资料查阅：2026-10-18（UTC）。适用：科技人物解说系列，抖音与小红书。配合[现有执行手册](README.md)及[发布记录模板](templates.csv)使用，不替代原有双审核要求。

以下是项目制作与运营检查方法，不是平台算法结论，也不是已经完成的验收记录。本次未核验两平台当前定时发布限制和 AI 声明页面，不新增相关政策断言；实际发布前仍须核当前官方说明和页面字段。公开仓库只保存方法与空模板，实际账号、后台回执和业务数据放在受控记录中。

## 1. 六项成片放行检查

每项记录“通过／失败／未检查”、最终版本、时间码、审核者与证据。失败或未检查均不能计入可发布库存。

| 项目 | 怎么查 | 不通过时怎么做 |
| --- | --- | --- |
| 主题句与主持位置 | 全屏人物说完完整主题句，按真实词尾和停顿缩窗；优先用同一连续镜头平滑落到固定左下。正常速度审看后续全片，核人物不漂移、不反复跳回全屏、不挡关键资料。 | 标出起止时间码，修接续或布局；不为固定秒数截断一句话。 |
| 切片动作连续 | 建立全部接缝清单，逐个看前后动作轨迹、头向、眼神、嘴形、肩线、光色和背景；先正常速度带声看，再逐帧定位。确认无重复动作、漏动作、冻帧、闪黑和假口型循环。 | 回到相邻源片与裁切点修复；单一接缝修好后仍完整复查最终导出。 |
| 手机字幕可读 | 对照实际口播核人名、年份、单位和否定词。最终编码文件在实体手机正常速度播放，不放大、不暂停仍能读完；另查两平台预览遮挡。字幕、主持、资料署名分区。 | 先缩短句子或调整断句、时长、字号与对比度；不得删掉事实限定或必需署名。桌面缩略预览仅算预检。 |
| 全片与跨片响度 | 用同一测量流程记录整片综合响度、响度范围和真峰值，并检查接缝及局部语句。选一条实际听审通过的参考片，在同一设备、固定播放音量下连续比较开头、中段、结尾，再完整听审新片。 | 查原源坏声、增益突变、背景音乐遮蔽和压限失真；先修源问题，不以统一峰值或自动增益掩盖缺句、嗡声。 |
| 真实动态素材 | 核每条素材的原始页面、真实事件日期、源窗入出点与实际画面；历史资料、训练、采访与示意各自标明性质。 | 缺来源或权利依据的素材退回待核／替换；不以照片轮播、平移缩放或重建画面冒充真实动态资料。 |
| 最终完整验收 | 两位指定审核者分别检查同一最终文件，留下独立完整视听结论；核字幕、事实、权利、首尾、接缝与手机播放，技术检查单另列。 | 有任何缺项维持待审；新导出生成新版本与哈希，重新审验，不能继承旧片“通过”。 |

响度建议：先为本系列记录参考片和项目目标／容差，再测量、调整、复测；不要把某个网上 LUFS 数字当成两平台统一强制标准。FFmpeg 的 loudnorm 文档区分综合响度、响度范围和真峰值，但这些指标不能证明听感与语义完整。[官方技术资料](https://www.ffmpeg.org/ffmpeg-filters.html#loudnorm)（2026-10-18 查阅）。

机器转写只用于发现可能漏字／错字，不能写成“人耳校准”。哈希用于确认文件身份和版本一致性，解码用于技术完整性检查，两者均不是内容质量保证。没有实际完整听过，就明确记录“完整听审未检查”。

## 2. 素材署名：在剪辑前解决

每条素材至少留一行：素材代号、作品名、作者／权利方、原始页面、许可名称与版本、许可页面、核验日期、源窗、修改方式、署名位置、其他限制、结论。

- 以具体素材页面的权利声明为准，“能下载”“机构官网提供”不等于可任意再发布。
- CC BY 4.0 要求适当署名、许可链接及修改说明；来源提供的版权／许可／免责声明等也应按条件保留。不要将 CC BY 的判断直接套用其他许可证。[CC BY 4.0 条款原文](https://creativecommons.org/licenses/by/4.0/legalcode.en)与[官方概要](https://creativecommons.org/licenses/by/4.0/)（2026-10-18 查阅）。
- 可复用署名骨架：“《作品名》— 作者／机构；来源：原始页面；许可：名称、版本及链接；修改：裁切／缩放／剪辑／配解说。”按实际素材补足权利方要求，不能虚填。
- NASA 指引要求标明来源，且官网可能使用第三方版权素材；NASA 的使用许可不自动传递给后来使用者。逐件核第三方署名，另核人物、标志及非背书要求。[NASA 官方指引](https://www.nasa.gov/nasa-brand-center/images-and-media/)（2026-10-18 查阅）。
- 片内／发布文案有“不放链接”的呈现要求时，先判断是否与所选许可兼容。仅在 Git 留研究链接不能自动满足成片传播时的署名条件；有冲突先替换素材或取得适当许可，不静默删链接后标合规。

## 3. 双平台排期与上传去重

一条独立内容设一个 content_id，一个批准导出设 release_id；每个平台分别记录状态与回执。标题改写、比例变化、重编码和双平台上传均不产生第二条独立内容。

提交前：
1. 同时查该平台的已发布、审核中、定时与草稿记录，核同一 content_id、release_id 和已有平台条目；同一文件哈希相同必然不能重复计数，哈希不同仍可能是同一内容。
2. 对两平台分别核账号、最终文件、封面、标题、署名、可见范围与所需声明，不能用一方通过代替另一方。
3. 每个平台写完整日期、本地时间、IANA 时区、当日 UTC 偏移、换算后 UTC，以及平台页面时区依据。不得从执行设备时区猜账号时区；无证据则保持 time_unverified。
4. 12:00／18:00 仅沿用既定项目档位。示例：若确认 Asia/Shanghai，2026-10-18 12:00 +08:00 对应 04:00Z，18:00 对应 10:00Z；示例不代表实际排期已确认。采用夏令时地区须按目标日期换算。
5. 提交一次后回读同一平台条目，保存状态和平台标识。超时或结果不明先查记录，不立即重传；无法判定则标“提交结果待核”。

定时成功只表示已安排。到期再核实际公开时间与可见状态；审核中、排期中、已公开分开记录。排期变更、替换或重传按该作品已有授权处理，本清单不新增发布权限。

## 4. 库存只数可用的独立成片

- “验收库存”：内容独立、完整、已清权、最终版本通过所需审核。
- “未分配库存”：验收库存中尚未分配给未来内容档位的作品；已经排期的作品只在其档位计一次，不再当作空闲备用。
- “五天覆盖”：未来五天十个内容档位逐一绑定不同 content_id，并分别核两平台可用／排期状态。某平台受阻不能报“双平台覆盖完成”。
- 一个内容在两平台各发一次仍只算一条；版本、片段、脚本、候选素材、待修片及已消费内容均不能凑库存。
- 简例：8 条独立验收成片加 2 个旧导出仍是 8 条；若其中 3 条已分配，则未分配库存为 5 条。该例仅演示计数，不是当前项目数据。

补货先按最早未覆盖档位排序，再看缺口类别：清权、人物片段、剪辑、听审或平台核验；不要为赶数量跳过质量关。

## 5. 生成额度停止后的续做清单

额度提示出现后停止新增生成请求，不盲目重试、不换路径规避限制。保存服务显示的限制范围与恢复信息；未明确恢复时间就记“未知”，不假设午夜重置。

可继续的工作：
- 核已完成任务及输出，避免恢复后重复生成；逐条区分成功、失败、结果不明。
- 完成事实表、真实动态素材清权、镜头表、字幕校对、封面草案及已有片段的接缝问题单。
- 对已有成片完成获准的技术检查与实际视听检查；缺听审保持待审。
- 整理双平台只读状态、独立库存与最早缺口，不把在途生成计入库存。
- 为每个待做片段留：content_id、片段代号、所需时间窗、输入版本、上下文动作、失败原因、已有产物、下一动作、依赖与验收条件。公开文档只留空模板，不放账号或私有媒体地址。

恢复前先核额度和已有任务结果；恢复后从最早缺口开始，只补缺失部分。每批输出先过源质量与接续检查，再进入合成、最终双审核、库存与授权发布流程。恢复额度本身不代表恢复产能或交付完成。
