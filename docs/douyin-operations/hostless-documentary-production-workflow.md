# 无主持人物纪录片：从锁稿到归档与排期的制作流程

版本日期：2026-11-16。本文是可复用的制作方法，不是平台流量公式、账号成绩或已完成发布的证明。

适用形式：**统一旁白 + 相关真实动态资料 + 有解释价值的动态图解 + 字幕**。与[运营手册](README.md)和[制作复盘手册](video-production-operations-review-public.md)配合使用；本文重点补齐无主持版本的生产衔接、局部修复、可复现归档和提交状态，不复制已有平台规则汇编。

## 0. 先确定交付形式，不让可选主持阻塞整片

- 无主持版是独立、明确的旁白纪录片，不冒称某位主持人的出镜版。取消主持画面后同步移除空人物框、空气泡和只为主持预留的空白布局。
- 历史人物是叙事对象，不将其肖像动画包装成现代主持，更不伪造当事人原声。现代旁白、历史引语、现代转述应可区分；非原话不要加引号冒充直接引用。
- 若另做主持版，使用已获批准且有权使用的固定人物与声音，检查口型、动作、入画退场连续性。此项单独验证，不把恢复主持作为所有无主持片的前置。
- 本流程可采用“至少 180 秒”的项目验收门槛，但这是制作约定，**不是抖音官方推荐阈值**。超过门槛仍须有内容深度，不能用变慢、重复、静默或长片尾凑数。

审核职责与必检项应在项目开始时明确。本流程将形式、技术检查、实际听审与综合编辑决策分别记录，不把固定审核人数或出镜布局当成适用于所有作品的通用规则。真实缺陷必须修复；未实际听审须如实标注，不冒充听过，也不单凭“未听审”就断言所有片均有缺陷。这不是平台允许免除听审的规则说明；有明确听审要求的交付仍须完成对应要求。

## 1. 全文与镜头计划先锁版

每个独立主题先回答四个问题：人物遇到什么问题，采用什么方法，有什么证据，观众能学到什么或理解什么社会意义。大众熟悉的人物也要有具体切口，不做生平清单、名言堆砌或只换名字的模板片。

锁版最小输入：

1. **全文**：逐句编号、事实来源、直接引语出处、必要的限定和不确定性。
2. **镜头计划**：段落编号、旁白句义、画面目的、真实资料或示意类别、必要标签与署名、候选素材源窗。
3. **声音约定**：批准的音色、自然语速、语言、已有配音的复用规则。
4. **版本清单**：每项文件名、版本号、内容指纹、修改原因与依赖关系。

先核因果、年代、数量级、人物身份和科学边界，再做音视频。稿件估算时长只能用于预算，不能当作成片实测时长。批准后保留只读快照；有改动产生新版本，不能悄悄覆盖原稿。

## 2. 以真实旁白为时间轴，只修有证据的坏段

先复用已合格的原配音，再处理实证缺陷。分段生成只是工程选择，不意味着每段必须等长；字幕和画面应贴合实际语音，而不是把声音拉进预设镜头长度。

- 保留最早可得的原音源，记录采样率、声道、样本数和指纹。将不合格版本隔离保留，避免误混入最终目录。
- 检查缺句、重复、长异常空白、非语音持续音、突变、末尾截断及明显不自然的语速；技术异常只产生候选问题，结合稿件与实际内容判断。
- 对已定位的坏句，优先保留可靠的完整句/语义块，只对需要替换的最小完整部分做一次定向修复；记录原段样本区间、替换句、拼接顺序和增益。不要按 ASR 的每个错字切碎音节。
- 一次修复仍失败时，先判断原因与允许的下一步，不进入自动无限重生成。已明确不可重试的额度或权限不得试探。
- 可删的完整冗余句若不影响问题、方法、证据、必要限制与段落衔接，可作编辑删改：重新核全文、镜头计划、字幕与实际时长，再锁新版本。不可删掉关键证据来掩盖坏声，也不能留下字幕替观众“读出”实际缺失的旁白。
- 自然停顿与异常空白分开处理，不靠插入静默、循环句子或放慢音频过时长门槛。
- 音量一致性按全片和逐段检查，保留增益记录；响度、峰值、相关性和无削波都不能单独证明听感自然。不同编码造成小差异时，不把“并非逐样本相同”直接判成内容损坏。

优先用无损 PCM 作中间母带，减少重复有损编码；只改画面且音轨可无损保留时，不必重新生成声音。任何局部修复都要检查其前后接缝、字幕归属及全片尾部。

## 3. 真实动态资料与动态图解各司其职

### 真实资料：先说明能证明什么

优先寻找与叙事事件、对象、年代直接相关且权利明确的动态记录。找不到同期记录时，不拿现代素材冒充；通用现代素材只能承担背景或类比功能，不能成为历史事实的“证据”。

每个实际使用的片段记录：公开来源页、作者/机构、许可与核验日、源文件指纹、源起止时间、最终位置、裁切/变速/消音等改动、可证明与不能证明的内容。页面上传时间不等于拍摄时间；地点未核就保留未核状态。

- 示例标签：“当代测量资料，非历史现场”“现代原理示意”“历史资料，年份已核”。标签须在实际编码画面中可读。
- 现代实验动作不自动证明历史人物使用过同一方法；读不清的仪器数值不承担精度论证。
- 有同期原声时，明确是否使用；删去原声后不要让现代配音看起来像画中人发言。
- 检查整个实际采用源窗及最终输出，不只看首中末。观察人物/标识、裁切边缘、黑帧、冻结、动作连续和关键关系。
- 静态照片的平移缩放仍是静态资料；增加一小段库存视频也不能自动让整片达到丰富、相关的动态叙事要求。不得用无关动态素材填充。

### 图解：变化必须增加解释

将“提出对象 → 展示关系 → 解释方法 → 给出证据或边界”做成逐步显现的图解。箭头、坐标、时间线、剖面、范围夹逼或流程的变化，应由对应旁白或语义节点触发，而不是整页静止只换字幕，也不是无意义抖动、缩放和飘动。

数值图检查单位、比例、坐标方向、舍入及不等号；示意不按比例时明确说明。现代推导与史料记载分开，推测的复原方法不能写成确定史实。动画不能为了好看移动数据点到错误位置。

## 4. 权利、署名与 AI 披露同时设计

公开可看、下载成功和注明来源都不等于获得复用权。事实引证与素材许可分开核。以 Pexels 为例，当前许可允许免费使用和修改、署名非强制，但仍限制误导背书、可识别人物的不当呈现等；不能把“免费”理解为无条件。[Pexels 官方许可](https://www.pexels.com/license/)（核读 2026-10-27）。

如果交付要求封面或片内无 URL/二维码，先选择能够兼容这一呈现的素材。素材要求保留许可链接而当前渠道无法满足时，换素材或取得适当许可，不能删掉义务后宣称合规。必要署名、历史资料年份和示意说明不属于可随意去除的制作杂字。

移除无关的制作占位字和非必要装饰水印，不等于去掉法定或平台要求的生成合成标识。《人工智能生成合成内容标识办法》第 3、10 条涵盖生成合成音频等内容，要求发布者主动声明并使用提供的标识功能；不得恶意删除或隐匿相关标识。AI 旁白应据实声明，不冒充当事人原声。[官方文本](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)（2025-09-01 施行；核读 2026-10-26）。

平台具体开关以当前发布界面为准，不把旧截图入口或另一平台规则直接套用。声明也不能替代事实、肖像及素材权利核查。

## 5. 字幕、封面与最终画面检查

字幕由实际旁白对应，按语义断句；人名、年月、数值、单位、引文和限定词逐项检查。字幕与补充图解文字分层，不能让图解被误认为旁白逐字稿。

- 在最终分辨率的真实编码帧上核字形边界、断行、对比度与显示时长，不只看排版坐标。保留给平台按钮、文案和屏幕裁切的空间；安全区按实际平台预览验证，不把某组像素坐标写成永久官方规范。
- 覆盖所有字幕条目、切换点、密集段、资料进入退出、修复接缝与首尾；抽帧和缩小预览可辅助，不能冒充实体手机或完整正常速度播放。
- 不让字幕、credit 和正文相互盖住，也不遮挡关键手部动作、仪器或图解值。
- 封面以主题人物或核心对象为主，短字、少层级，与内容承诺一致；不用 URL、二维码或堆叠大段简介。历史人物的现代生成形象须避免被误认成档案照片。

## 6. 验收要分层，不让单项检测代替结论

每次验收绑定同一最终文件指纹。状态可用“通过 / 失败 / 未检查 / 证据不足”，并写检查范围及结论依据：

| 层次 | 要确认什么 | 不能据此声称什么 |
| --- | --- | --- |
| 内容与事实 | 问题、方法、证据、价值完整；限定准确 | 有引用就一定有内容深度 |
| 素材与视觉 | 权利、标签、相关性、动态图解、字幕实际像素 | 首中末三帧等于全片通过 |
| 实际音频完整性 | 语义覆盖、源链、接缝、首尾、异常片段 | ASR 相符等于真实听审 |
| 技术 | 实测时长、流信息、全片解码、帧/样本/时间戳 | 解码通过等于好听或事实正确 |
| 主观视听与设备 | 实际执行的回放、听审、手机检查 | 未执行项目已通过 |
| 综合编辑决策 | 已知缺陷处理结果、未查范围、是否达到交付目标 | 所有未查项都是已知缺陷 |
| 平台提交 | 实际上传、转码、定时保存及公开结果 | 点击发布或出现缩略图等于发布成功 |

FFprobe 可以输出容器和媒体流的结构化信息，适合测量和记录，不负责判断内容深度或听感。[FFprobe 官方文档](https://ffmpeg.org/ffprobe.html)（核读 2026-10-26）。测量时同时看容器与音视频流、首尾时间范围；容器超过 180 秒并不证明有效讲述达到目标。

未实际听过就保留“未实际听审”。已证实的缺句、坏声、误导素材或数学错误必须修复；有局部疑点就定位受影响片段，不将一个主题的问题扩大成全部已验收作品的统一阻塞。已验收文件未变且无新缺陷证据时，沿用可追溯结论，不重复生成；改过的文件重新核变更和受影响范围。

## 7. 去重库存与可复现归档

库存以**独立合格主题**计数：同片多平台、分辨率、封面、修订版不重复计；脚本、配音、素材、候选和局部预览另列。建议同时列“已排未发”“合格待排”“待修”“素材准备”，不混成一个可发布数字。若采用每天两条的计划，覆盖天数 = 独立合格未发主题数 ÷ 2；已发布作品不再占未来库存。

每片保留两层归档：

1. **可交付成片包**：最终视频、封面、字幕、发布文案和干净清单。清单含主题 ID、版本、文件名、字节数、SHA-256、实测时长、编辑验收结论及未查范围。
2. **受控恢复包**：锁稿、镜头计划、可合法保存的声音/图解/编辑后画面、构建说明、工具版本和依赖、源窗与增益记录、文件校验清单。含受限素材的恢复包保持非公开，权利不允许再分发的原素材不随公开模板分发。

“已上传云盘”需回读对象、大小或校验信息；必要时取回验证。不要用本地文件存在或另一个云服务的备份替代目标云盘成功。重名先查版本与指纹，未知结果先查再重传，默认不扩大分享权限。

“可复现”也分级记录：文件校验通过、从包内材料完成重建、解码/内容核对通过、字节级一致分别说明。编码环境不同可能无法字节级一致；未运行重建就只称恢复材料已准备，不能称已验证可复现。

公开 Git 只存本流程、空白模板和公开来源。实际账号、作品后台、私有素材、凭证、私密路径及未授权数据不入库。

## 8. 发布是一项单独的有状态操作

发布前先核实际账号、已有作品和草稿、同主题重复版本、既有排期、界面时区与当前操作方。正在由其他人操作或提交结果未知时，先核状态，避免抢占窗口和双重提交。不要重做已排作品或擅改旧排期。

- 选定真实合格文件及封面，逐项核标题、文案、可见范围、必要署名和 AI 声明。
- 固定北京时间 12 点/18 点等时段只是可选运营约定，不是流量保证。按目标日期转换时区；保存目标时间、界面时间、时区及 UTC 偏移。
- 夏令时切换可能造成重复或不存在的本地时刻。Python `zoneinfo` 使用 IANA 规则并支持 `fold`，但转换工具不能证明发布页面采用同一时区或数据版本。[官方说明](https://docs.python.org/3/library/zoneinfo.html)。先核界面依据，再核保存结果，不复用恒定时差。
- 上传、转码、定时保存、到时公开分别记录。后台条目回读确认具体日期时间，才计“已排”；到时还要核是否实际公开。
- 可见页面操作应一步一核：文件选择 → 进度 → 编辑 → 提交 → 作品列表。接口或输入调用返回成功并不等于界面动作成功。
- 崩溃、网络错误、确认弹窗、额度和反自动化提示分别识别。结果不确定先读已有结果，不能盲目重发；一次失败不能证明额度耗尽或平台封禁。修复需有实质变化再验证，不无限刷新，不绕权限或确认。
- 软件安装、重启、网络设置、额外费用和素材替换分别按授权边界处理；恢复控制会话不等于重启浏览器或云电脑。

本流程本身不证明任何真实作品已上传、已排期或已公开。

## 9. 一条作品的最小交接清单

复制到自己的非公开工作记录，空白不表示已经通过：

- 独立主题 / 本片问题 / 方法、证据和观众价值：
- 形式：无主持 / 另行批准的主持版；版本与最终 SHA-256：
- 锁稿与镜头计划版本；原声音来源及局部修改：
- 动态资料使用区间、权利依据、必要标签与署名：
- 图解事实、字幕完整性和实际画面检查：
- 容器 / 音频 / 视频实际时长及首尾覆盖：
- 技术检查、主观听审、手机检查分别的状态和范围：
- 已知缺陷及处理；综合编辑结论和责任人：
- 成片包、恢复包与云盘回读结果；实际重建验证级别：
- 平台账号核对、重复作品/草稿检查、操作方确认：
- 目标日期时间、页面时区、偏移和保存后回读结果：
- 上传 / 转码 / 已排 / 实际公开的独立状态：

终点不是“生成任务已返回”，而是合格文件可追溯、交付可取回、发布状态可核实。内容生产、云盘备份、公开方法同步和平台排期可以并行，但不能互相冒充完成。


## 10. 实操：把一篇人物故事变成可接手的工程

下面是生产配方，不是已经生成影片的回执。`<项目>`、日期和输出名都应替换为自己的值；示例输出必须写入新的版本目录。工具安装、联网取材与生成语音需另行具备相应权限和合法输入。不要复制任何项目的私有路径、账号、任务号或真实素材指纹到公开仓库。

### 10.1 事实表 → 完整稿 → 20 段精确输入

1. 建立事实表：`claim_id / 准备说的话 / 来源标题与公开页 / 原文定位 / 证据能支持的范围 / 不确定性 / 稿件句号`。优先原始文献、机构档案与学术资料；转述不是原话，现代复原不是历史原物，提出年份不是发明起点。逐句核实，不让配音或图解替史料补空白。
2. 以“问题—选择—方法—结果—限制—意义”写完整自然中文。结尾回答开头问题，并给出有依据的理解；至少 180 秒来自足量的新事实和解释，不来自字数指标、慢放、循环或片尾垫时。
3. 将全文切成 S01–S20 的完整语义块，段长可不同。保存 `script/segments.json`，每项有 `id`、`text`、`claim_ids`；正文拼接须与锁稿逐字一致。20 段只是本配方的交接粒度，不是平台或 TTS 服务规定。
4. 将每段 `text` 原样编码为 UTF-8，文件末尾是否有换行要明确；TTS 输入只含该段正文，不含段号、镜头说明、文件名或审核文字。分别保存正文指纹、音色配置来源、发音表与实际返回文件映射。数字、古人名、专业词的读法先确定，不依靠自动改写。
5. 优先复用已经合格且有权使用的原配音；需要新生成时保持同一合法音色与自然语速。一次任务可要求交回 20 个独立无损音频和清单，但服务不支持时按其真实能力调整，不能假定“单任务必交20段”或“额度已刷新”。
6. 请求中明确不改写、不漏句、不重复、不念段号、不加音乐、不伪造历史人物原声。请求被接受、任务完成、附件可下载、20 段可解码是四个不同状态；先查已有任务和返回结果再决定是否重试。不要因下载失败重做已生成音频。

### 10.2 样本主时钟：连续母带优先，画面只在全局末尾补不足一帧

将所有段转成**同一采样率、声道数、PCM 位深**后再计数。保留原件；如确需重采样，重新测量并重新对齐字幕。每声道的 sample frame 数记为 N，时长为 N/R；立体声不能把两个声道标量之和当作 N。Python `wave.getnframes()` 返回音频帧数；本配方限定整数 PCM，避免不同 Python 版本的浮点 WAV 支持差异。[Python wave 文档](https://docs.python.org/3/library/wave.html)（核读 2026-10-27）。

本目录附带 [production-sample-clock.py](production-sample-clock.py)，只使用 Python 标准库：验证 S01–S20 格式、拼接原始 PCM 字节、产生累计半开区间 `[start_sample,end_sample)`，并用精确有理数输出全局帧边界。它**不调用 TTS，不生成画面，不判断好听与语义完整**。

```sh
# 在新的项目版本目录运行；clock-build 必须不存在
python3 production-sample-clock.py --audio audio --out clock-build --fps 30
# 使用 30000/1001 等精确帧率时，不要改写为近似小数
python3 production-sample-clock.py --self-test
```

音频母带保持连续，不按逐段视频时长补音频静默。设累计样本 S、帧率 F，画面切点选 `ceil(S*F/R)`；每段画面帧数是相邻累计边界之差，整片总帧数仅为 `ceil(总样本*F/R)`。不是对每段时长分别 ceil 后再相加。极短段得到零帧时应合并画面事件，不强塞一帧。更多数学边界见已有[样本时钟学习记录（固定版本）](https://github.com/15302252173/super-skills/blob/f0410c0e37b56fb104d5e46fd9ca738da6544265/docs/douyin-operations/sample-clock-and-frame-boundaries-2026-10-27.md)。

渲染器在第 f 帧使用全局时刻 `f/F` 查找场景、字幕和语义事件，再转换成该场景局部样本坐标；不得在每场重新从零累计已取整秒数。字幕每条至少存 `text / start_sample / end_sample / segment_id`：语义对齐后核全文覆盖、顺序、边界和实际显示帧，导出 SRT/ASS 时才转换成其时间精度。字幕不能机械平均分配；ASR 仅辅助定位，需核漏句和限定词。

如需按样本截取一个修复区间，先填写自己的整数边界，再执行：

```sh
# A/B 是同一 PCM 母带上的整数样本边界，B 为第一个不保留的样本
A=0; B=24000
ffmpeg -n -i audio/master.wav \
  -af "atrim=start_sample=${A}:end_sample=${B},asetpts=PTS-STARTPTS" \
  -c:a pcm_s24le audio/excerpt-v001.wav
```

`atrim` 不自动重置时间戳；`concat` 滤镜可能按较长流推进并给较短音频补静默，不能与 concat demuxer 混为一谈。以上模板不做拼接与增益；修复后仍需听接缝并重建全片时轴。[FFmpeg atrim / concat 官方说明](https://ffmpeg.org/ffmpeg-filters.html)（核读 2026-10-27）。

### 10.3 画面和音频合成：不是把静态页拉长到够秒数

按每段关键句填写镜头卡：`绝对样本区间 / 真实动态资料源窗 / 图解变化 / 持续限定标签 / 必要署名 / 字幕留白`。真实资料完整检查所用源窗，标明它是同期历史记录、当代环境还是现代实验；图解必须有解释性动作。通用工程镜头不能证明某座历史工程，现代工艺演示不能证明古代作坊的具体过程。无声图解候选、短演示和状态 PNG 不计作合格整片。

生成从 0 起连续编号的 `frames/000000.png` 等，数量必须等于全局总帧数；先核没有缺号、旧版本余帧或意外重复。图解源码、随机种子、字体及其许可随恢复包保留；真实素材若不允许再分发，不打包原片。必要时保留有权保存的**最终已编辑窗**，也不因此宣称脱离许可约束。

以下为通用编码模板，不是本仓库自带人物画面生成器：须先自行生成合格完整帧序列、核清元数据/生成合成标识义务，且运行目录中有对应母带。`TOTAL_FRAMES` 从时钟 JSON 读取，`FPS` 与该 JSON 一致：

```sh
FPS=30
TOTAL_FRAMES=$(python3 -c 'import json; print(json.load(open("clock-build/sample-clock.json"))["total_video_frames"])')
ffmpeg -n -framerate "$FPS" -start_number 0 -i frames/%06d.png \
  -i clock-build/master.wav -map 0:v:0 -map 1:a:0 \
  -frames:v "$TOTAL_FRAMES" -c:v libx264 -pix_fmt yuv420p -crf 20 \
  -c:a aac -b:a 192k -movflags +faststart final/review-v001.mp4
ffprobe -v error -count_frames -show_streams -show_format -of json \
  final/review-v001.mp4 > qa/probe-v001.json
ffmpeg -v error -xerror -i final/review-v001.mp4 \
  -map 0:v:0 -map 0:a:0 -f null -
sha256sum final/review-v001.mp4 > qa/final-v001.sha256
```

目录须预先建立；不要加 `-shortest` 掩盖短流截尾，也不要用 `-t 180` 截断完整旁白。AAC 有编码延迟/尾部填充，检查解码内容与首尾时间，不能要求它和 PCM 文件逐字节相同。若仅改画面并复用已验收 AAC，可在确认轨道、起点和全长一致后使用 `-c:a copy`，再提取音频流比对；“复制成功”仍不等于新声画关系已通过。

### 10.4 真实声画联审与验收门

在**同一个最终 SHA-256** 上完整正常速度播放，实际听声音并同时看画面：逐句是否完整自然，字幕是否跟上，说到的对象是否正在画中，原理图变化是否准确，必要限定是否来得及看清。修复接缝、资料进入退出和尾句加查。纯音频听审、静音视觉检查、ASR、抽帧、解码各记录自己的范围，不能互相替代，也不能把“工具未报错”写成“全片好听”。按项目既定双审核要求执行，不因本模板的自动检查而减免。

最低放行记录应含：有效完整讲述达到项目时长、全文与字幕覆盖、相关真实动态资料、原创图解边界、权利/署名/AI 披露、全解码、完整声画联审、手机可读性、已知缺陷关闭。无法实际听审时标“未检查”，不虚构通过；已知坏声、误导或缺句不得进入合格库存。只有全片合格的独立主题计 1；同题 v001/v002、竖横版和多平台包不重复增加库存。

## 11. Muse 到底做了什么：可照着执行的分工与交接教程

本节更新于 2026-10-28。以下“已用过”仅指本制作链中留存输入、调用回执和返回文件能够证明的使用方式，**不是 Muse 产品功能大全，也不保证其他版本或账号具备相同能力**。所有例子已泛化；任务提示词是供新项目填写的模板，不是某次私有任务原文。

### 11.1 已实际使用的环节，与没有证据的能力分开

| 环节 | 本方法中的执行方与实际做法 | 不应误称为 |
| --- | --- | --- |
| 调研、事实表、完整稿、20段锁稿 | 在 Muse 外完成；给 Muse 的是确定正文，不让它临时扩写史实 | Muse 自动考证全部历史事实 |

| 声画联审、恢复包、私有备份、平台提交 | 在各自环节独立执行、分别回读 | Muse 的技术报告替代实际听审、备份或发布成功 |

原生 MP3 已经是有损编码；将其解码为 PCM16 是为了稳定编辑，不会恢复 MP3 中已经丢失的信息。原 MP3 与同源 WAV 都保留，后续不要反复 MP3→MP3 转码。

已记录的声音配置是 `voice=avocado_v2:MAI_01`、`voice2=null`、`language=zh`，使用当时自然默认速度（输入记录称 default100），不另传 `--speed`，原音量与原风格保持不变。**voice/voice2 有实际调用回执支持；语言、默认速度及“不另改音量风格”来自输入与技术记录，不把回执未返回的参数伪装成机器验证过的字段。** 这些是复现线索，不是任何新账号的可用性或音色权利保证；开始前核对当前可用工具与合法音色。

没有核实的音高、seed、风格 ID、数值增益、模型子版本不自行补填。本方法没有以成片证据验证 Muse 的视频生成、真人连续主持或唇形同步能力，也没有核实统一收费、免费额度、每日刷新时间；不把“没有费用弹窗”写成免费。需要主持版时另做获准人物、声音、连续性和口型测试，不让它阻塞明确的无主持版。

### 11.2 步骤 A：先把可执行输入准备好，再交给 Muse

1. 按第 10.1 节完成事实表和锁稿，确认 S01–S20 唯一、顺序正确、每段是完整语义块。文件名、段号、画面说明不能混进朗读正文。
2. 为每段准备 `inputs/S01.txt` 等 UTF-8 文件。本模板选择**无 BOM、无末尾换行**；这是交接约定，不是服务强制要求。记录这些精确输入的 SHA-256；若改正文，建立新锁稿版本，不覆盖旧版。
3. 将难读人名、年代和术语整理成文字发音说明；不得让服务为“更自然”自行删掉不确定性和证据限制。正文的数字写法若要调整，应先改锁稿再生成，而不是事后让字幕掩盖声音差异。
4. 在提交前查同主题同版本是否已有任务或完成附件。任务状态未知时先读结果，不新发另一份。此处查重是为了避免重复计算和重复作品，不是要求上传整套私有素材。
5. 以下脚本可由 `segments.json` 生成精确文本目录，**只写本地文件、不调用 Muse**。JSON 顶层是20项数组，每项含 `id`、`text`；`text` 不含换行。`tts-inputs-v001` 必须不存在。

```python
from pathlib import Path
import hashlib, json
segments = json.loads(Path("segments.json").read_text(encoding="utf-8"))
assert len(segments) == 20
assert [s["id"] for s in segments] == [f"S{i:02}" for i in range(1, 21)]
assert all(isinstance(s["text"], str) and s["text"].strip()
           and not any(c in s["text"] for c in "\r\n\ufeff") for s in segments)
out = Path("tts-inputs-v001")
out.mkdir(exist_ok=False)
manifest = []
for s in segments:
    body = s["text"].encode("utf-8")
    name = s["id"] + ".txt"
    (out / name).write_bytes(body)
    manifest.append({"id": s["id"], "file": name,
                     "utf8_bytes": len(body), "sha256": hashlib.sha256(body).hexdigest()})
(out / "inputs-manifest.json").write_text(
    json.dumps(manifest, ensure_ascii=False, indent=2) + "\n", encoding="utf-8")
```

### 11.3 步骤 B：给 Muse 的可复用首轮任务提示词

将尖括号内容替换、附上全部20段正文/输入文件后再提交；不要真的让它朗读占位符。以下是自然语言任务模板，**不是宣称存在这些参数的 Muse API 或命令行脚本**。

```text

本轮不自动重生成失败段；保留原始结果，等待明确的定向修复范围。

用当前任务支持的原生附件返回 ZIP：音频、输入、回执、ASR、检查报告和 SHA-256 清单。
若附件不可下载或生成未完成，准确报告当前状态；不要因此重生成已有音频，
不要擅换分享权限或外部交付渠道。未知费用/额度保持未知，不承诺免费或某时刷新。
```

若服务不能读取附件，应通过受支持输入方式按段粘贴已锁正文，并核实际输入回显；不要把“引用了一个不可读文件路径”当成已经交付文本。任务费用、权限或限制出现时按真实状态处理，不绕过限制。

### 11.4 步骤 C：音频文件合同与下载核验

建议约定以下逻辑结构，实际返回文件名可以不同，但必须有逐段映射，不能靠猜文件排序。回执中的私有对象 ID、下载地址和运行路径只保留在受控原件，不随公开教程上传。

```text
audio-batch-v001.zip
  inputs/S01.txt … S20.txt
  native/S01.mp3 … S20.mp3
  pcm/S01.wav … S20.wav
  receipts/S01.json … S20.json
  asr/S01.txt … S20.txt
  report.json
  manifest.json
  SHA256SUMS.txt
```

`manifest.json` 每段至少对应：段号、精确输入文件/摘要、原生音频文件/摘要、PCM文件/摘要、实际格式、样本数、实际时长、回执文件、ASR文件和技术状态。额外保留 `subjective_listening: NOT_PERFORMED`，直到真实听审完成；不要把 `HEALTHY` 机械标签解释为最终合格。`report.json` 应记录缺失/失败/疑点和转换步骤，不写无依据的成功率。

下载与验证按以下顺序：

1. 下载原生附件并保留原 ZIP。先列目录、核压缩包完整性，拒绝绝对路径、`..`、符号链接及异常解压体积；通过检查后解到全新目录，不覆盖已有原件。
2. 核 S01–S20 均有输入和音频，逐段输入与自己锁稿字节相同。只比较中文字符数不足以证明一致；标点、数字与限定词也要核。
3. 查看校验清单，确认只含包内相对文件、无越界引用后再校验；发送方清单证明传输一致，不证明内容可信。接收方再独立计算摘要与样本数。
4. 全部音频实际解码，检查 PCM 格式与实际样本数。ASR 和波形检查用于找疑点；原音与原生MP3都保留，不以“归一化版本听起来更响”覆盖原件。
5. 只有文件已落地可读，才进入本地母带阶段。附件暂不可取时保留任务结果并报告；“生成成功”与“本地可用”分开记录。

以下命令在已经安全解包并检查清单的目录执行，不涉及重新生成：

```sh
sha256sum -c SHA256SUMS.txt
ffprobe -v error -show_streams -show_format -of json pcm/S01.wav
ffmpeg -v error -xerror -i pcm/S01.wav -map 0:a:0 -f null -
# 对 S01–S20 全量执行，不把 S01 一段通过写成全批通过
```

### 11.5 步骤 D：只补真正坏的部分，好声原样保留

先根据实际听审、文本覆盖和异常证据定位失败，而不是按 ASR 分数机械重做。存在整段坏声就补完整段；若前半句群可靠，仅后缀失效，可保留原可靠前缀，给 Muse **完整的新后缀语义块**。不要截半个音节，也不要每个错字各合成一次。

定向任务模板：

```text
仅生成 <段号>/<修复版本> 的以下完整正文：
<精确后缀或整段正文>

其余段和此前可靠音频不要重生成；不要在输出中重复原保留前缀。
使用本片已核实的同一音色与自然默认语速，本次仅一次定向生成。
交回该输入、原生 MP3、同源 PCM16 WAV、调用回执、ASR、技术报告及校验清单。
不要为追求时长拉慢、循环、补静默或删句；若仍失败，保留结果并明确说明，不自动继续试。
```

后续在 Muse 外执行：按半开样本区间提取原可靠部分，与新完整语义块连接；记录每个成分来源、样本范围、固定增益和输出范围。原音不动，派生母带另存版本。24位PCM中间文件用于后续处理，不能说把16位或MP3来源变成了更高原始录音质量。实际听前后接缝，重新检查整段与全片首尾；任何改稿同步更新锁稿、字幕和镜头事件。

### 11.6 步骤 E：从 Muse 音频继续到完整影片

1. **接收20段合格源 → 母带**：先做必要修复与统一格式，再运行第10.2节样本时钟脚本；自然语音总时长决定画面，不把 Muse 估算时长当成实际结果。
2. **母带 → 字幕**：每句锁稿绑定实际样本区间，逐项核全文覆盖；ASR 辅助定位，但展示字幕不能来自未经校对的识别文本。
3. **字幕/语义事件 → 画面**：本地原创图解按语义节点变化，合法真实动态资料按源窗剪辑并持续标注身份边界；依第10.3节全局帧网格合成。无主持版不需要捏造 Muse 主持或唇形步骤。
4. **编码 → 联审**：同一最终文件实际完整正常速度声画回放，分别核事实、声音、画面、字幕、署名及AI声明。技术报告、下载成功和原生任务完成均不能代替这一关。
5. **验收 → 恢复/备份**：源码、母带、字幕映射和有权保存的视觉材料构成干净离线恢复包，真正在新目录重建并校验；私有备份下载回读。公开 Git 只同步方法与通用代码，不自动公开原音、素材或任务附件。
6. **备份 → 发布**：仅在另有发布授权时进入平台，查重、核时区、保存后回读；拟定12点/18点、音频完成与实际已排三个状态不混用。

接手者应能回答：“哪段声音是原生生成的，哪段是后缀修复的，哪些处理发生在 Muse 外，最终文件实际检查了什么？”答不出时先补来源映射，不把教程中的操作模板当成已经执行的完成记录。

### 11.8 公开素材检索与接收方核验：书写画面不能只看题名

补充日期：2026-11-15。本次协作中，Muse 实际完成的是按缺失镜头功能查找公开作品页和许可信息，交回候选清单；下载、媒体检查、抽帧辨识与带标签的短素材剪辑在 Muse 外完成。清单交付不等于素材已下载，更不等于视频生成或整片验收。

### 11.9 页面证据、原件与实际回放分层，受阻不越界

补充日期：2026-11-15。近期新增素材研究阶段，Muse 完成了公开来源作品页研究、逐件许可核对，并有一次下载尝试被访问验证阻挡后停止；另有既存文件的库存与媒体参数盘点。**新研究候选没有因此完成原件校验、抽帧或连续观看验收，也没有因此产出新成片。** 这一范围说明不否认第11.1节记录的较早旁白交付，不把不同批次的实际分工混在一起。本次手册整理本身只是归纳已有记录。

每件素材分别填写四层证据，不跨层代认：

1. **作品页描述**：记录页面所称题名、作者、时长、许可及核对日期。页面描述不是实际画面检查，所称时长不等于已下载版本的实测时长。

### 11.10 历史证据分层与研究纠错

补充日期：2026-11-16。该轮 Muse 实际只整理既有文字资料核查与纠错记录，未生成音视频、未做实际听审或成片验收；不改变前述其他批次分工。

- 区分史料原文、后世记述、学者推断与新闻转载。原文支持什么命题要结合语境判断，不因文字存在就当事实已证；后世记述注明成书时代及与所述事件的时间距离，同时代材料缺失须限定为已检查范围或“据现存材料”。
- 推断保留“应是”“可信为”等限定。根据人物贬谪年份推定某篇作品的创作时间，必须说明推断依据，不能写成史料明载。
- 记录实际读到的版本与转载链。通稿转载不是原公告已读，期刊文章转载页不是学术机构原站；未读原件保持未读。
- 出土残字经释读、断代和出土背景核验后，可支持对应文本在相关时期的存在或流传；不能据此直接证明人物生平、具体作年或籍贯。篇题不自动等于作者，文字相似也不自动确定作品归属。
- 错误撤回须留痕：记录原说法、问题、证据边界和替换表述，保留旧资料而不再沿用错误。同步受影响的事实表、锁稿、字幕及图解；只更新教程不等于作品已修复或验收。

### 12.2 逐句合成与变速后的单一时间轴

1. 锁定全文与事实表，按完整语义切句。章节数、句数由内容决定；14章或20段都只是组织方式，不是硬编码要求。第10.2节附带脚本按20段设计，其他结构不能不经调整就宣称适用。
2. 复用已配置且获准的固定音色。共享合成资源用进程锁等方式串行占用，防止多任务混写；保存每句的精确输入、输出、采样格式、样本数、时长与校验值。
3. 保存原速波形；技术检查覆盖空文件、截断、异常静音与全文覆盖，专名发音和自然度仍须实际听审。
4. 需要提速时，在独立派生版本明确记录处理链。本地制作记录存在一次 `atempo=1.10` 保音高提速的做法，也有原速版本；1.10不是所有人物或所有声音的推荐值。不要叠加提速，不用减速或空白填时长。
5. 音频处理后重测实际时长，以最终母带重新生成字幕和镜头时轴。固定倍率可以帮助换算候选边界，但最终编码时间仍需校验；不可沿用处理前的字幕时间后直接称同步完成。
6. 响度目标只是工程参数，不能证明听感好或词句完整。原音、派生音和最终编码音分别记录，不覆盖来源。

### 12.3 字幕标明对齐精度，画面标明真实类别

逐句真实音频边界可提供可靠的句级区间；句内按文本长度分配只是估时，**不能称逐字强制对齐**。人工检查长句、停顿、引诗、数字和专名，修正提前消失、跨句和拖尾；在最终编码帧查看双行字幕及图解文字是否相撞。

将每个镜头分为以下类别，再按实际使用记录：

- AI生成静态情境画：标示艺术示意，不当作历史人物真实相貌、历史影像或可靠建筑复原。平移缩放不改其静态来源属性。
- 程序原创动画：对象、关系、几何或过程本身随时间变化；画面变化须帮助解释，不仅移动整张画。数学图逐步检查共线、比例、单位和计算，现代演示数字与史料数字分开。
- 许可明确的真实动态资料：重新核来源及权利、实际源窗和使用方式。现代竹林、田园、手作等可作意象，不能证明古代地点或人物现场。只计实际入片区间，不把备用素材计入动态时长。

这三类可以组合，也可按题材采用原创数学动画等形式；不能用一个笼统的“动态视频”标签掩盖素材差异。主体要求若有改变，先核当前项目约定。

### 12.4 交付说明与真实验收分开保存

成片包可包含视频、对应比例封面、SRT、发布文案及制作说明。制作说明写明事实来源、画面类别、声音来源、处理链、字幕精度和未查项目；公开视频中的署名及AI声明仍按许可和平台要求落实。

技术解码、波形、响度、静音检测、逐镜抽帧、事实复核各有价值，但不替代完整正常速度声画回放。交付包写“未完整实际听审”时，该状态必须保留，不能被“文件已生成”“已备份”或检测无报错覆盖。本流程已有完整联审要求，未完成者继续标为待审，不计合格待排库存。

返工后绑定新的最终文件指纹，重查受影响句段、镜头和接缝；全片最终验收、备份回读与平台状态各自确认。公开教程只记录可复用方法，不以本节更新宣称任何真实影片已通过验收或新增排期。


### 12.5 环境丢失后的恢复：先验原件，再补缺失部分

补充日期：2026-11-14。连接恢复不代表原工作盘仍在，也不代表旧进程或文件可用。先核项目目录、最终文件和恢复清单；历史“已生成”回执只证明当时的状态。

1. 按获准范围依次检查原私有备份、持久文件库和既有协作项目的附件；先列已有对象和版本，不因一次本地缺失立即重做全部。
2. 对找回的原媒体计算 SHA-256，与可信旧清单比较，另核字节数、媒体流及全解码。摘要相同支持字节身份，不替代权利与内容审核；仍要确认来源许可及实际采用源窗。
3. 找回稿件、镜头计划或源码的文字记录，可据此重建，但新文件单独编号并计算新摘要。没有旧字节就不得标“原文件恢复”或假填旧哈希。
4. 无法找回的部分，在已有重建授权内补做；保存已恢复输入与新生成输出的映射，避免重做可复用音轨、已验收成片或已排作品。
5. 恢复原工具时核官方来源、批准模型与预设、依赖版本和小段测试。能加载或合成不等于主观听感通过，测试成功也不自动代表整批完成。
6. Muse 可只承担第11.7节的既有资产窄范围盘点，返回“未找到”也是有效结果；不要将这种盘点写成 Muse 已生成旁白、视频、主持或恢复整个工程。下载、生成和上传需分别有实际记录。

### 12.6 逐句 PCM 边界字幕：用已知句界，不猜句内时码

在每个独立音频只对应一条锁稿句、顺序和内容已核对的前提下，可采用整句字幕消除按字数估计的子句切换。依据第10.2节统一格式后的 PCM 样本数，句 i 的区间为累计半开区间 `[S_i,S_i+N_i)`，显示时刻分别为 `S_i/R` 与 `(S_i+N_i)/R`。不要每句先四舍五入再累计；导出字幕时才转换为格式支持的时间精度。

- 这是音频文件级的精确句界，不是词、音节或句内停顿的精确对齐。原句若含前后静音、错读或漏词，样本边界不能消除这些问题。
- 长句可在同一条字幕内按语义换行；行数和字号必须在最终画面验证，不把“三行”固定为所有屏幕的规则。来不及阅读时先调整呈现或句子结构，不靠提前切字伪装同步。
- 如仍需分成多个字幕事件，使用真实对齐证据并复核，不再将文本长度比例当已确认同步。
- 修改音频、重采样、删句、修复或变速后，以最终编辑音轨重建句界及后续所有区间，再检查编码首尾与接缝。保存原轨，不能用新时轴覆盖旧版本的来源记录。

### 12.7 分层持久检查点与定向疑点记录

在易中断的制作环境中，不必等整片完成才保全工程。按明确白名单分层保存：**锁稿与事实表 → 合法素材及许可 → 音轨、逐句输入回执和样本时间线 → 图解源码与依赖 → 候选片及检查报告**。每层有独立版本、字节数、摘要和依赖清单；保留一个已验证恢复点，后续用增量或新版本补齐，不覆盖唯一原件。

每个检查点都回读目标对象并核版本、大小，必要时取回比对摘要。保存成功、能取回、能重建、最终验收是不同状态；候选检查点始终标待审，不计合格库存。私有文件库的检查点也不冒充指定私有云盘已备份，更不自动授予公开分享权。恢复包的内容清理、许可及离线测试仍遵循第10.5节。

技术报告与疑点表分开：

- 全解码、响度、真峰值、黑帧和静默检测只报告工具版本、阈值、范围及结果；无命中不证明自然度、语义或同步合格。
- ASR 逐句对应锁稿，区分专名近音、数字格式、普通词替换、缺句和重复。记录源音频摘要、模型、转写原文、句号与时间码，不把机器错字直接判成真实错读。
- 多模型同向异常可提高复核优先级，仍不是实际听审。只对证据指向的最小完整句做有界对照，保留原件；对照结果不确定先解释原因，不无限换种子直到转写“看起来正确”。
- 明确列出已经实际听审、仅机器检查与尚未检查的范围。局部疑点不扩散为所有影片不合格，技术通过也不覆盖综合编辑验收要求。


### 12.8 许可冲突后的定点替换：源窗、标签与音轨分别验证

补充日期：2026-11-18。本节归纳在 Muse 外完成的局部画面修复与独立复核方法；Muse 的既有材料研究不能记成这些剪辑、编码或最终验收。没有实际执行的连续观看与听审仍按未检查记录。

1. **先处理证据冲突，不扩大推断。** 搜索摘要、旧清单和当前作品页许可正文不一致时，保留各自出处与核验时间，暂停对具体素材的放行。机构名称或同站另一素材的公有领域声明不覆盖本件；若有可信原下载许可记录，明确其适用对象和时间，不凭网页变化自动认定旧授权失效。定点证据仍不足时，在授权范围内替换受影响源窗，不将局部问题扩大为全部影片的缺陷。
2. **原作品与实际镜头一一对应。** 对合集来源记录具体子项，而非仅记合集标题。可用关键帧、构图与裁切关系辅助匹配，注明是抽帧对照；相似风景、题名或作者相同都不足以证明同源。页面匹配、许可闭合与采用源窗的内容检查分别记录。
3. **替换范围落到帧号。** 场景检测只提供候选切点；核每个出入点前后相邻帧，将时间区间映射到实际帧率和半开帧区间。保留不受影响的画面、原字幕与合法署名。若用原创动态图解替代实拍，明确为原理或证据关系示意，不伪造现场，也不因替换就宣称全片为真实动态。
4. **检查标签跨镜头残留。** 不只检查新画面的中间帧；出点后的第一帧也可能残留旧地点、旧资料名或覆盖条。同步核顶部身份限定、底部署名与字幕层，确认它们服务当前镜头而非前一段；实际剔除受约束素材，不能只删许可链接或署名。
5. **只改画面时独立证明原音保留。** 对复制音轨比较一致方法提取的编码包内容摘要，并核包数、首尾时间及全片解码；不要拿整个新旧视频的文件摘要比较音轨。容器时间戳或封装变化另记，编码包内容一致也不保证新画面与声音同步，更不证明已经听审。重新绑定最终文件指纹，复查修复接缝、字幕及全片时长，保留旧版和修复映射。

这类定点修复、独立封面补齐和文案完善不会增加独立主题数量；归档、排期与实际公开继续分别回读。

### 12.9 素材找回与配音接收分开验收

- 在候选索引中区分「找到原件位置」「已取回且可解码」「许可已核」「已接入可用路径」。保留可信旧摘要；字节或摘要不符时另存为候选，不覆盖原件。对现代实拍另核画面是否明确注明时间地点及非历史现场；授权页、画面标签和使用区间缺一项就单独标记，不把素材齐全等同于验收完成。
- 配音交接按段绑定锁稿文本摘要、音源许可记录与实际音频文件。缺音频、文本版本不符或来源未确认时不输出正式时轴；待完整解码并测得实际音频长度后，再生成分段边界。实测配时不是实际听审，也不能证明台词读对。
- 既有协作项目可以协助核查是否已有音源、交付和任务，不因显示连接就认定在生成；没有生成交付时，不把素材盘点或配音接收准备归为生成成果。

### 12.11 补画面帧预算与无字幕工作样片

本节补充第10.2节的样本主时钟和第12.3、12.6节的字幕精度说明，不重复配音生成与验收流程。

- **源素材预算与输出边界不是同一次取整。** 原创补画面的源帧预算可按 `ceil(实际缺口秒数 × 帧率)` 准备，保留足量内容，再按统一时间轴裁尾，不循环或减速。第10.2节采用累计边界向上取整；若某个工作样片选择最近帧舍入，则明确记录 `round(累计样本 × 帧率 / 采样率)` 的规则，相邻累计边界之差才是段帧数，单边界误差不超过半帧。不要把分别取整的段长相加，也不要混用两种规则而不更新清单。最近帧舍入可能使末帧边界早于音频末端；需要保证全长覆盖时，末端采用向上取整并验证，不截音频迁就画面。
- **工作样片与带字幕交付分开。** 保留无字幕画面轨，可先与连续原配音封装成明确标注的工作样片供验收。验证分段PCM顺序连接、视频复制后的编码包一致性、起点、各段边界误差、音视频端点和全轨解码；不为凑齐逐段视频时长向音频加静默。字幕返工时复用画面，工作样片仍不计合格库存，不代表已听审或可发布。
- **真实合成块边界不自动成为句界。** 一次合成返回的块可能含多句或不对应完整语义。样本数能证明块边界，不能证明块内词句时码。按文本长度分配再靠近低能量停顿，只是暂定定位；低能量不等于语义停顿，不能标成强制对齐。保存其暂定状态与真实块锚点，字幕经内容对应核验后再进入交付；不以检测结果冒充实际听辨。

- **字幕句界与跨镜头位置分开处理。** 已核 cue 的文字及 PCM 起止样本保持不变；为避让不同镜头中的图解或署名，需要改变位置时，只将该 cue 的呈现拆成相邻子事件，并按实际整数帧切点切换位置。不要用估算秒数、段长或字幕格式的舍入时间代替真实切帧，也不要为修位置而移动语音句界、截字或改音频。保留原 cue 与各呈现子事件的映射，检查切点没有双重字幕、空白或旧位置残留。
- **切帧验收看最终编码的相邻帧。** 约定新镜头首帧编号为 `n`，从同一最终输出顺序解码并按帧号提取 `n−1`、`n`，同时检查前后邻帧的字幕位置、完整文字和标签。浮点秒数 seek 或播放器近似定位可能落到邻帧，不能用作边界通过的唯一证据。帧号、时间基准与是否恒定帧率须明示；可变帧率素材使用实际帧时间戳，不把 `n/fps` 当精确时刻。验证只证明检查过的画面边界，不替代实际听审。

### 12.12 等长实拍插入：镜头内布局与逐帧不变量

本节补充第12.8节的定点替换与第12.11节的字幕呈现拆分，仅涉及已核许可且与旁白相关的当代过程资料，不改变历史证据的边界。

- **用同样的 N 帧替换，而非延长时间轴。** 对同帧率的恒定帧率源与输出，锁定目标半开区间 `[a,b)`，令 `N=b-a`，以原速连续采用源窗中恰好 N 帧；不循环、不减速、不增加停帧。源与输出帧率不一致时，不能同时假定一对一帧数与原速时长不变，应先明确帧率转换及时间映射，再复核。记录来源原件与采用源窗的对应关系、作者署名、许可依据和裁切；明确标示“当代过程示意，非历史现场”等时间角色，不把现代动作当成古代原件或当事人行为的证据。
- **一个连续镜头采用一个稳定字幕安全区。** 新镜头跨过旧版本的布局切点时，不机械继承旧位置切换。依据新镜头的关键动作、署名和标签，统一该镜头内的字幕位置；只有真实镜头或明确内容需求改变时，才按第12.11节拆分呈现事件。已核 cue 的文字及起止边界不变，不为布局修复改旁白。
- **逐输出帧核可见文字与修复边界。** 对修复窗中的每一输出帧核对该帧应显示的完整 cue，确认无漏字、截字、重复字幕、空档或旧位置残留，而非只比较字幕文件。检查进入、退出及相邻帧，确认新素材和新覆盖层没有出现在批准的内部修复窗之外。全片重新编码时，不把外窗编码字节变化等同于画面内容改变；另行核受控画面区域与时间轴是否保持。
- 音轨按第12.8节保留并核对原编码旁白载荷，连同总帧数、时长、最终解码和字幕结果一起绑定新文件指纹。上述逐帧与载荷检查不冒充实际听审，也不单独证明整片已可发布。
