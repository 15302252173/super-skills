# 无主持人物纪录片：从锁稿到归档与排期的制作流程

版本日期：2026-10-27。本文是可复用的制作方法，不是平台流量公式、账号成绩或已完成发布的证明。

适用形式：**统一旁白 + 相关真实动态资料 + 有解释价值的动态图解 + 字幕**。与[运营手册](README.md)和[制作复盘手册](video-production-operations-review-public.md)配合使用；本文重点补齐无主持版本的生产衔接、局部修复、可复现归档和提交状态，不复制已有平台规则汇编。

## 0. 先确定交付形式，不让可选主持阻塞整片

- 无主持版是独立、明确的旁白纪录片，不冒称某位主持人的出镜版。取消主持画面后同步移除空人物框、空气泡和只为主持预留的空白布局。
- 历史人物是叙事对象，不将其肖像动画包装成现代主持，更不伪造当事人原声。现代旁白、历史引语、现代转述应可区分；非原话不要加引号冒充直接引用。
- 若另做主持版，使用已获批准且有权使用的固定人物与声音，检查口型、动作、入画退场连续性。此项单独验证，不把恢复主持作为所有无主持片的前置。
- 本流程可采用“至少 180 秒”的项目验收门槛，但这是制作约定，**不是抖音官方推荐阈值**。超过门槛仍须有内容深度，不能用变慢、重复、静默或长片尾凑数。

审核职责与必检项应在项目开始时明确。本流程将形式、技术检查、实际听审与综合编辑决策分别记录，不把固定审核人数或出镜布局当成适用于所有作品的通用规则。真实缺陷必须修复；未实际听审须如实标注，不冒充听过，也不单凭“未听审”就断言所有片均有缺陷。这不是平台允许免除听审的规则说明；有明确听审要求的交付仍须完成对应要求。

## 1. 全文与镜头计划先锁版

每个独立主题先回答四个问题：人物遇到什么问题，采用什么方法，有什么证据，观众能学到什么或理解什么社会意义。大众熟悉的人物也要有具体切口，不做生平清单、名言堆砌或只换名字的模板片。

锁版最小输入：

1. **全文**：逐句编号、事实来源、直接引语出处、必要的限定和不确定性。
2. **镜头计划**：段落编号、旁白句义、画面目的、真实资料或示意类别、必要标签与署名、候选素材源窗。
3. **声音约定**：批准的音色、自然语速、语言、已有配音的复用规则。
4. **版本清单**：每项文件名、版本号、内容指纹、修改原因与依赖关系。

先核因果、年代、数量级、人物身份和科学边界，再做音视频。稿件估算时长只能用于预算，不能当作成片实测时长。批准后保留只读快照；有改动产生新版本，不能悄悄覆盖原稿。

## 2. 以真实旁白为时间轴，只修有证据的坏段

先复用已合格的原配音，再处理实证缺陷。分段生成只是工程选择，不意味着每段必须等长；字幕和画面应贴合实际语音，而不是把声音拉进预设镜头长度。

- 保留最早可得的原音源，记录采样率、声道、样本数和指纹。将不合格版本隔离保留，避免误混入最终目录。
- 检查缺句、重复、长异常空白、非语音持续音、突变、末尾截断及明显不自然的语速；技术异常只产生候选问题，结合稿件与实际内容判断。
- 对已定位的坏句，优先保留可靠的完整句/语义块，只对需要替换的最小完整部分做一次定向修复；记录原段样本区间、替换句、拼接顺序和增益。不要按 ASR 的每个错字切碎音节。
- 一次修复仍失败时，先判断原因与允许的下一步，不进入自动无限重生成。已明确不可重试的额度或权限不得试探。
- 可删的完整冗余句若不影响问题、方法、证据、必要限制与段落衔接，可作编辑删改：重新核全文、镜头计划、字幕与实际时长，再锁新版本。不可删掉关键证据来掩盖坏声，也不能留下字幕替观众“读出”实际缺失的旁白。
- 自然停顿与异常空白分开处理，不靠插入静默、循环句子或放慢音频过时长门槛。
- 音量一致性按全片和逐段检查，保留增益记录；响度、峰值、相关性和无削波都不能单独证明听感自然。不同编码造成小差异时，不把“并非逐样本相同”直接判成内容损坏。

优先用无损 PCM 作中间母带，减少重复有损编码；只改画面且音轨可无损保留时，不必重新生成声音。任何局部修复都要检查其前后接缝、字幕归属及全片尾部。

## 3. 真实动态资料与动态图解各司其职

### 真实资料：先说明能证明什么

优先寻找与叙事事件、对象、年代直接相关且权利明确的动态记录。找不到同期记录时，不拿现代素材冒充；通用现代素材只能承担背景或类比功能，不能成为历史事实的“证据”。

每个实际使用的片段记录：公开来源页、作者/机构、许可与核验日、源文件指纹、源起止时间、最终位置、裁切/变速/消音等改动、可证明与不能证明的内容。页面上传时间不等于拍摄时间；地点未核就保留未核状态。

- 示例标签：“当代测量资料，非历史现场”“现代原理示意”“历史资料，年份已核”。标签须在实际编码画面中可读。
- 现代实验动作不自动证明历史人物使用过同一方法；读不清的仪器数值不承担精度论证。
- 有同期原声时，明确是否使用；删去原声后不要让现代配音看起来像画中人发言。
- 检查整个实际采用源窗及最终输出，不只看首中末。观察人物/标识、裁切边缘、黑帧、冻结、动作连续和关键关系。
- 静态照片的平移缩放仍是静态资料；增加一小段库存视频也不能自动让整片达到丰富、相关的动态叙事要求。不得用无关动态素材填充。

### 图解：变化必须增加解释

将“提出对象 → 展示关系 → 解释方法 → 给出证据或边界”做成逐步显现的图解。箭头、坐标、时间线、剖面、范围夹逼或流程的变化，应由对应旁白或语义节点触发，而不是整页静止只换字幕，也不是无意义抖动、缩放和飘动。

数值图检查单位、比例、坐标方向、舍入及不等号；示意不按比例时明确说明。现代推导与史料记载分开，推测的复原方法不能写成确定史实。动画不能为了好看移动数据点到错误位置。

## 4. 权利、署名与 AI 披露同时设计

公开可看、下载成功和注明来源都不等于获得复用权。事实引证与素材许可分开核。以 Pexels 为例，当前许可允许免费使用和修改、署名非强制，但仍限制误导背书、可识别人物的不当呈现等；不能把“免费”理解为无条件。[Pexels 官方许可](https://www.pexels.com/license/)（核读 2026-10-27）。

如果交付要求封面或片内无 URL/二维码，先选择能够兼容这一呈现的素材。素材要求保留许可链接而当前渠道无法满足时，换素材或取得适当许可，不能删掉义务后宣称合规。必要署名、历史资料年份和示意说明不属于可随意去除的制作杂字。

移除无关的制作占位字和非必要装饰水印，不等于去掉法定或平台要求的生成合成标识。《人工智能生成合成内容标识办法》第 3、10 条涵盖生成合成音频等内容，要求发布者主动声明并使用提供的标识功能；不得恶意删除或隐匿相关标识。AI 旁白应据实声明，不冒充当事人原声。[官方文本](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)（2025-09-01 施行；核读 2026-10-26）。

平台具体开关以当前发布界面为准，不把旧截图入口或另一平台规则直接套用。声明也不能替代事实、肖像及素材权利核查。

## 5. 字幕、封面与最终画面检查

字幕由实际旁白对应，按语义断句；人名、年月、数值、单位、引文和限定词逐项检查。字幕与补充图解文字分层，不能让图解被误认为旁白逐字稿。

- 在最终分辨率的真实编码帧上核字形边界、断行、对比度与显示时长，不只看排版坐标。保留给平台按钮、文案和屏幕裁切的空间；安全区按实际平台预览验证，不把某组像素坐标写成永久官方规范。
- 覆盖所有字幕条目、切换点、密集段、资料进入退出、修复接缝与首尾；抽帧和缩小预览可辅助，不能冒充实体手机或完整正常速度播放。
- 不让字幕、credit 和正文相互盖住，也不遮挡关键手部动作、仪器或图解值。
- 封面以主题人物或核心对象为主，短字、少层级，与内容承诺一致；不用 URL、二维码或堆叠大段简介。历史人物的现代生成形象须避免被误认成档案照片。

## 6. 验收要分层，不让单项检测代替结论

每次验收绑定同一最终文件指纹。状态可用“通过 / 失败 / 未检查 / 证据不足”，并写检查范围及结论依据：

| 层次 | 要确认什么 | 不能据此声称什么 |
| --- | --- | --- |
| 内容与事实 | 问题、方法、证据、价值完整；限定准确 | 有引用就一定有内容深度 |
| 素材与视觉 | 权利、标签、相关性、动态图解、字幕实际像素 | 首中末三帧等于全片通过 |
| 实际音频完整性 | 语义覆盖、源链、接缝、首尾、异常片段 | ASR 相符等于真实听审 |
| 技术 | 实测时长、流信息、全片解码、帧/样本/时间戳 | 解码通过等于好听或事实正确 |
| 主观视听与设备 | 实际执行的回放、听审、手机检查 | 未执行项目已通过 |
| 综合编辑决策 | 已知缺陷处理结果、未查范围、是否达到交付目标 | 所有未查项都是已知缺陷 |
| 平台提交 | 实际上传、转码、定时保存及公开结果 | 点击发布或出现缩略图等于发布成功 |

FFprobe 可以输出容器和媒体流的结构化信息，适合测量和记录，不负责判断内容深度或听感。[FFprobe 官方文档](https://ffmpeg.org/ffprobe.html)（核读 2026-10-26）。测量时同时看容器与音视频流、首尾时间范围；容器超过 180 秒并不证明有效讲述达到目标。

未实际听过就保留“未实际听审”。已证实的缺句、坏声、误导素材或数学错误必须修复；有局部疑点就定位受影响片段，不将一个主题的问题扩大成全部已验收作品的统一阻塞。已验收文件未变且无新缺陷证据时，沿用可追溯结论，不重复生成；改过的文件重新核变更和受影响范围。

## 7. 去重库存与可复现归档

库存以**独立合格主题**计数：同片多平台、分辨率、封面、修订版不重复计；脚本、配音、素材、候选和局部预览另列。建议同时列“已排未发”“合格待排”“待修”“素材准备”，不混成一个可发布数字。若采用每天两条的计划，覆盖天数 = 独立合格未发主题数 ÷ 2；已发布作品不再占未来库存。

每片保留两层归档：

1. **可交付成片包**：最终视频、封面、字幕、发布文案和干净清单。清单含主题 ID、版本、文件名、字节数、SHA-256、实测时长、编辑验收结论及未查范围。
2. **受控恢复包**：锁稿、镜头计划、可合法保存的声音/图解/编辑后画面、构建说明、工具版本和依赖、源窗与增益记录、文件校验清单。含受限素材的恢复包保持非公开，权利不允许再分发的原素材不随公开模板分发。

“已上传云盘”需回读对象、大小或校验信息；必要时取回验证。不要用本地文件存在或另一个云服务的备份替代目标云盘成功。重名先查版本与指纹，未知结果先查再重传，默认不扩大分享权限。

“可复现”也分级记录：文件校验通过、从包内材料完成重建、解码/内容核对通过、字节级一致分别说明。编码环境不同可能无法字节级一致；未运行重建就只称恢复材料已准备，不能称已验证可复现。

公开 Git 只存本流程、空白模板和公开来源。实际账号、作品后台、私有素材、凭证、私密路径及未授权数据不入库。

## 8. 发布是一项单独的有状态操作

发布前先核实际账号、已有作品和草稿、同主题重复版本、既有排期、界面时区与当前操作方。正在由其他人操作或提交结果未知时，先核状态，避免抢占窗口和双重提交。不要重做已排作品或擅改旧排期。

- 选定真实合格文件及封面，逐项核标题、文案、可见范围、必要署名和 AI 声明。
- 固定北京时间 12 点/18 点等时段只是可选运营约定，不是流量保证。按目标日期转换时区；保存目标时间、界面时间、时区及 UTC 偏移。
- 夏令时切换可能造成重复或不存在的本地时刻。Python `zoneinfo` 使用 IANA 规则并支持 `fold`，但转换工具不能证明发布页面采用同一时区或数据版本。[官方说明](https://docs.python.org/3/library/zoneinfo.html)。先核界面依据，再核保存结果，不复用恒定时差。
- 上传、转码、定时保存、到时公开分别记录。后台条目回读确认具体日期时间，才计“已排”；到时还要核是否实际公开。
- 可见页面操作应一步一核：文件选择 → 进度 → 编辑 → 提交 → 作品列表。接口或输入调用返回成功并不等于界面动作成功。
- 崩溃、网络错误、确认弹窗、额度和反自动化提示分别识别。结果不确定先读已有结果，不能盲目重发；一次失败不能证明额度耗尽或平台封禁。修复需有实质变化再验证，不无限刷新，不绕权限或确认。
- 软件安装、重启、网络设置、额外费用和素材替换分别按授权边界处理；恢复控制会话不等于重启浏览器或云电脑。

本流程本身不证明任何真实作品已上传、已排期或已公开。

## 9. 一条作品的最小交接清单

复制到自己的非公开工作记录，空白不表示已经通过：

- 独立主题 / 本片问题 / 方法、证据和观众价值：
- 形式：无主持 / 另行批准的主持版；版本与最终 SHA-256：
- 锁稿与镜头计划版本；原声音来源及局部修改：
- 动态资料使用区间、权利依据、必要标签与署名：
- 图解事实、字幕完整性和实际画面检查：
- 容器 / 音频 / 视频实际时长及首尾覆盖：
- 技术检查、主观听审、手机检查分别的状态和范围：
- 已知缺陷及处理；综合编辑结论和责任人：
- 成片包、恢复包与云盘回读结果；实际重建验证级别：
- 平台账号核对、重复作品/草稿检查、操作方确认：
- 目标日期时间、页面时区、偏移和保存后回读结果：
- 上传 / 转码 / 已排 / 实际公开的独立状态：

终点不是“生成任务已返回”，而是合格文件可追溯、交付可取回、发布状态可核实。内容生产、云盘备份、公开方法同步和平台排期可以并行，但不能互相冒充完成。


## 10. 实操：把一篇人物故事变成可接手的工程

下面是生产配方，不是已经生成影片的回执。`<项目>`、日期和输出名都应替换为自己的值；示例输出必须写入新的版本目录。工具安装、联网取材与生成语音需另行具备相应权限和合法输入。不要复制任何项目的私有路径、账号、任务号或真实素材指纹到公开仓库。

### 10.1 事实表 → 完整稿 → 20 段精确输入

1. 建立事实表：`claim_id / 准备说的话 / 来源标题与公开页 / 原文定位 / 证据能支持的范围 / 不确定性 / 稿件句号`。优先原始文献、机构档案与学术资料；转述不是原话，现代复原不是历史原物，提出年份不是发明起点。逐句核实，不让配音或图解替史料补空白。
2. 以“问题—选择—方法—结果—限制—意义”写完整自然中文。结尾回答开头问题，并给出有依据的理解；至少 180 秒来自足量的新事实和解释，不来自字数指标、慢放、循环或片尾垫时。
3. 将全文切成 S01–S20 的完整语义块，段长可不同。保存 `script/segments.json`，每项有 `id`、`text`、`claim_ids`；正文拼接须与锁稿逐字一致。20 段只是本配方的交接粒度，不是平台或 TTS 服务规定。
4. 将每段 `text` 原样编码为 UTF-8，文件末尾是否有换行要明确；TTS 输入只含该段正文，不含段号、镜头说明、文件名或审核文字。分别保存正文指纹、音色配置来源、发音表与实际返回文件映射。数字、古人名、专业词的读法先确定，不依靠自动改写。
5. 优先复用已经合格且有权使用的原配音；需要新生成时保持同一合法音色与自然语速。一次任务可要求交回 20 个独立无损音频和清单，但服务不支持时按其真实能力调整，不能假定“单任务必交20段”或“额度已刷新”。
6. 请求中明确不改写、不漏句、不重复、不念段号、不加音乐、不伪造历史人物原声。请求被接受、任务完成、附件可下载、20 段可解码是四个不同状态；先查已有任务和返回结果再决定是否重试。不要因下载失败重做已生成音频。

推荐最小目录（只放相对路径，私有交付包不等于公开 Git）：

### 10.2 样本主时钟：连续母带优先，画面只在全局末尾补不足一帧

将所有段转成**同一采样率、声道数、PCM 位深**后再计数。保留原件；如确需重采样，重新测量并重新对齐字幕。每声道的 sample frame 数记为 N，时长为 N/R；立体声不能把两个声道标量之和当作 N。Python `wave.getnframes()` 返回音频帧数；本配方限定整数 PCM，避免不同 Python 版本的浮点 WAV 支持差异。[Python wave 文档](https://docs.python.org/3/library/wave.html)（核读 2026-10-27）。

本目录附带 [production-sample-clock.py](production-sample-clock.py)，只使用 Python 标准库：验证 S01–S20 格式、拼接原始 PCM 字节、产生累计半开区间 `[start_sample,end_sample)`，并用精确有理数输出全局帧边界。它**不调用 TTS，不生成画面，不判断好听与语义完整**。

```sh
# 在新的项目版本目录运行；clock-build 必须不存在
python3 production-sample-clock.py --audio audio --out clock-build --fps 30
# 使用 30000/1001 等精确帧率时，不要改写为近似小数
python3 production-sample-clock.py --self-test
```

音频母带保持连续，不按逐段视频时长补音频静默。设累计样本 S、帧率 F，画面切点选 `ceil(S*F/R)`；每段画面帧数是相邻累计边界之差，整片总帧数仅为 `ceil(总样本*F/R)`。不是对每段时长分别 ceil 后再相加。极短段得到零帧时应合并画面事件，不强塞一帧。更多数学边界见已有[样本时钟学习记录（固定版本）](https://github.com/15302252173/super-skills/blob/f0410c0e37b56fb104d5e46fd9ca738da6544265/docs/douyin-operations/sample-clock-and-frame-boundaries-2026-10-27.md)。

渲染器在第 f 帧使用全局时刻 `f/F` 查找场景、字幕和语义事件，再转换成该场景局部样本坐标；不得在每场重新从零累计已取整秒数。字幕每条至少存 `text / start_sample / end_sample / segment_id`：语义对齐后核全文覆盖、顺序、边界和实际显示帧，导出 SRT/ASS 时才转换成其时间精度。字幕不能机械平均分配；ASR 仅辅助定位，需核漏句和限定词。

如需按样本截取一个修复区间，先填写自己的整数边界，再执行：

```sh
# A/B 是同一 PCM 母带上的整数样本边界，B 为第一个不保留的样本
A=0; B=24000
ffmpeg -n -i audio/master.wav \
  -af "atrim=start_sample=${A}:end_sample=${B},asetpts=PTS-STARTPTS" \
  -c:a pcm_s24le audio/excerpt-v001.wav
```

`atrim` 不自动重置时间戳；`concat` 滤镜可能按较长流推进并给较短音频补静默，不能与 concat demuxer 混为一谈。以上模板不做拼接与增益；修复后仍需听接缝并重建全片时轴。[FFmpeg atrim / concat 官方说明](https://ffmpeg.org/ffmpeg-filters.html)（核读 2026-10-27）。

### 10.3 画面和音频合成：不是把静态页拉长到够秒数

按每段关键句填写镜头卡：`绝对样本区间 / 真实动态资料源窗 / 图解变化 / 持续限定标签 / 必要署名 / 字幕留白`。真实资料完整检查所用源窗，标明它是同期历史记录、当代环境还是现代实验；图解必须有解释性动作。通用工程镜头不能证明某座历史工程，现代工艺演示不能证明古代作坊的具体过程。无声图解候选、短演示和状态 PNG 不计作合格整片。

生成从 0 起连续编号的 `frames/000000.png` 等，数量必须等于全局总帧数；先核没有缺号、旧版本余帧或意外重复。图解源码、随机种子、字体及其许可随恢复包保留；真实素材若不允许再分发，不打包原片。必要时保留有权保存的**最终已编辑窗**，也不因此宣称脱离许可约束。

以下为通用编码模板，不是本仓库自带人物画面生成器：须先自行生成合格完整帧序列、核清元数据/生成合成标识义务，且运行目录中有对应母带。`TOTAL_FRAMES` 从时钟 JSON 读取，`FPS` 与该 JSON 一致：

```sh
FPS=30
TOTAL_FRAMES=$(python3 -c 'import json; print(json.load(open("clock-build/sample-clock.json"))["total_video_frames"])')
ffmpeg -n -framerate "$FPS" -start_number 0 -i frames/%06d.png \
  -i clock-build/master.wav -map 0:v:0 -map 1:a:0 \
  -frames:v "$TOTAL_FRAMES" -c:v libx264 -pix_fmt yuv420p -crf 20 \
  -c:a aac -b:a 192k -movflags +faststart final/review-v001.mp4
ffprobe -v error -count_frames -show_streams -show_format -of json \
  final/review-v001.mp4 > qa/probe-v001.json
ffmpeg -v error -xerror -i final/review-v001.mp4 \
  -map 0:v:0 -map 0:a:0 -f null -
sha256sum final/review-v001.mp4 > qa/final-v001.sha256
```

目录须预先建立；不要加 `-shortest` 掩盖短流截尾，也不要用 `-t 180` 截断完整旁白。AAC 有编码延迟/尾部填充，检查解码内容与首尾时间，不能要求它和 PCM 文件逐字节相同。若仅改画面并复用已验收 AAC，可在确认轨道、起点和全长一致后使用 `-c:a copy`，再提取音频流比对；“复制成功”仍不等于新声画关系已通过。

### 10.4 真实声画联审与验收门

在**同一个最终 SHA-256** 上完整正常速度播放，实际听声音并同时看画面：逐句是否完整自然，字幕是否跟上，说到的对象是否正在画中，原理图变化是否准确，必要限定是否来得及看清。修复接缝、资料进入退出和尾句加查。纯音频听审、静音视觉检查、ASR、抽帧、解码各记录自己的范围，不能互相替代，也不能把“工具未报错”写成“全片好听”。按项目既定双审核要求执行，不因本模板的自动检查而减免。

最低放行记录应含：有效完整讲述达到项目时长、全文与字幕覆盖、相关真实动态资料、原创图解边界、权利/署名/AI 披露、全解码、完整声画联审、手机可读性、已知缺陷关闭。无法实际听审时标“未检查”，不虚构通过；已知坏声、误导或缺句不得进入合格库存。只有全片合格的独立主题计 1；同题 v001/v002、竖横版和多平台包不重复增加库存。

### 10.5 干净离线恢复与私有回读

先用白名单构建新恢复目录，**不要整个工作目录打包后再赌没有隐私**。只纳入锁稿、音频、许可允许的视觉输入/编辑缓存、源码、字体许可、依赖版本、最终文件和必要检查说明。清除临时链接、绝对私有路径、账号配置、密钥、下载令牌、内部聊天/诊断及过期候选；不删除必要素材授权、署名或生成标识。恢复代码通过 `Path(__file__).resolve()` 等定位包内相对路径，不回访原工程。

```sh
# 在待归档包根目录运行；用明确文件白名单替换下面的示例
sha256sum script/segments.json audio/master.wav code/rebuild.py \
  final/review-v001.mp4 > SHA256SUMS.txt
sha256sum -c SHA256SUMS.txt
# 真实生产须覆盖全部必需输入（含字体、缓存和依赖锁定文件），不能只校四项

python3 code/rebuild.py --out ../reconstructed-v001
```

最后一条是**恢复脚本接口约定**，不是本仓库提供的完整渲染脚本；制作时必须交付实际实现。恢复测试使用已准备好依赖的隔离环境，禁止联网、禁止读取包外素材，不自动安装软件。记录：全输入校验、真正完成全片重建、全轨解码、内容/首尾/字幕核对、是否字节一致。仅检查 zip CRC 或“源码在包里”不能称离线重建成功。字节一致依赖编码器、字体与工具版本；不同版本生成不同字节时保留差异，不修改期望哈希来伪造通过。

私有备份遵循目标存储的受支持流程：上传后回读目标对象版本、大小，再下载到新目录比对 SHA-256；权限仍保持私有。成片包与恢复包分别确认，不把其中一个成功写成两个都成功。备份记录不进公开 Git。

### 10.6 拟排期不等于平台已排

只在私有记录中维护 `拟定 → 已上传 → 已转码 → 已保存定时 → 已公开`；每次状态变化须有对应平台回读。北京时间 12:00/18:00 是示例编辑节奏，不保证流量。先检查同主题、草稿和既有排期，保留已排文件，不自动覆盖。目标日期必须明确，页面时区必须实测；若页面为其他地区，用该日期的 IANA 时区规则转换，不硬编码时差。

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo
# 演示日期与界面地区，实际运行必须替换为已确认值
bj = datetime(2026, 11, 1, 18, 0, tzinfo=ZoneInfo("Asia/Shanghai"))
ui = bj.astimezone(ZoneInfo("America/Los_Angeles"))
print("北京", bj.isoformat(), "UTC", bj.astimezone(timezone.utc).isoformat())
print("界面", ui.isoformat(), "fold", ui.fold)
```

转换不操作平台，也不证明平台时区正确；夏令时重复小时要核偏移和 `fold`，保存后再次回读日期、时间和时区，到时再核实际公开。只有制作或 Git 同步授权，不意味着可以发布视频、修改排期或扩大云盘权限。
